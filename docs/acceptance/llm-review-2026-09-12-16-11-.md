# LLM 审查（glm-5.1）

> 材料来源：material-M15-bindings.md

## 结论
**有条件通过** —— 静态代码逻辑与数据结构设计严谨，r1/r2/r3 遗留问题均已妥善修复，但因核心验收点强依赖运行时黑盒验证，静态审查无法完全证实其实证有效性。

## 逐项核对

1. **两档案不同模型时，各槽位请求路由到各自绑定档案**
   - *可判定*：代码逻辑支持。附录 B `resolveProfileForSlot(slot)` 实现了槽位绑定优先解析。调用点清单及 `generateWriting` 必传 `slot` 参数设计（编译期强制归槽）能保证路由通道建立。
   - *疑点/无法判定*：材料声称 T1/T3/T4/T5 双档案路由断言通过，但静态审查无法核实假服务器日志与 CDP 驱动的真实请求 payload 中的 `model` 名，需黑盒验证。
2. **未绑定槽位回落默认；`bindings:set(slot,'')` 删绑定回落**
   - *可判定*：代码完全证实。`resolveProfileForSlot` 中 `const bound = bindRes.data.find(...)` 若无匹配则走 `profiles.find(p => p.id === defRes.data)`。`bindings.ts` 中 `setBinding` 对 `profileId === ''` 执行 `DELETE` 操作，逻辑自洽。
3. **删除档案后对应槽位绑定级联清零（FK CASCADE）**
   - *可判定*：表结构设计支持。`database.ts` 迁移 v15 明确声明 `REFERENCES api_profiles(id) ON DELETE CASCADE`，且材料指出 `db.pragma('foreign_keys = ON')` 既有事实。
   - *无法判定*：SQLite 的 FK 级联强依赖运行时 `pragma` 状态，静态无法确保连接时未被关闭。
4. **绑定重启持久**
   - *可判定*：绑定数据落库至 `agent_bindings` 表，无内存缓存阻断，重启后必从磁盘加载。
5. **设置分区 8 行渲染+即改即存**
   - *可判定*：`SlotBindingsSection.vue` 代码完整。遍历 `AGENT_SLOTS` 渲染，`@change` 触发 `onPick` 调用 IPC 入库。r1/r2/r3 修复均已在 diff 中体现（`:disabled="saving !== ''"` 全局禁用、空档案 `v-else` 引导、catch 块 `await load()` 回拉）。
6. **typecheck 三重闸门+console 零报错+自测零外部 AI 消耗**
   - *无法判定*：属纯运行时与开发环境状态，静态审查无法证实。

## 发现的问题

- **低危（设计瑕疵/语义偏差）：** `SlotBindingsSection.vue` 中，获取默认档案名逻辑为 `pRes.data.find((p) => p.id === dRes.data)?.name ?? pRes.data[0]?.name ?? ''`。若用户默认档案 ID 指向已删除的档案，UI 会将库中「第一个档案」的名字显示为当前默认档案名，可能对用户造成误导（实际生成会回落到第一个档案，但 UI 提示未明确说明是「回落」）。
- **低危（理论竞态）：** `bindings.ts` 的 `setBinding` 函数中，先调用 `getProfile(profileId)` 验证存在，再执行 `INSERT...ON CONFLICT DO UPDATE`。在极高频并发删除档案的场景下，存在校验通过但写入前档案被删的 TOCTOU 竞态。虽 `resolveProfileForSlot` 有防御性兜底不会崩溃，且 SQLite 单写特性降低了概率，但不够严谨。

## 无法判定项

1. **运行时路由断言真实性**：T1/T3/T4/T5 等声称通过假服务器验证路由到不同 `model`，需黑盒测试抓包验证真实 HTTP 请求体。
2. **FK CASCADE 运行时状态**：需运行时执行删档案操作后查询 `agent_bindings` 表是否真清零。
3. **调用点完备性**：材料提供了 14 个调用点清单并声称全集无遗漏，但 diff 截断导致部分调用点（如 `GenesisView.vue`、`CanvasView.vue` 等）的改动无法在本次 diff 中逐一核实。
4. **Typecheck 与 Console 零报错**：需实际运行 `npm run typecheck` 并在 Electron CDP 中观察 console。
