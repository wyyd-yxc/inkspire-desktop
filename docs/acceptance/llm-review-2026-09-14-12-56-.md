# LLM 审查（glm-5.1）

> 材料来源：material-M17-visual.md

## 结论
不通过：核心防闪白（FOUC）逻辑在「跟随系统」模式下存在严重遗漏，且 `html` 底色未响应 `data-theme` 属性，导致启动与重载阶段必定出现视觉错乱。

## 逐项核对
1. **双主题切换生效且持久**：**否**。`src/main/index.ts` 中 `darkPredicted` 仅判断了 `theme === 'dark' || (theme === '' && ...)`，完全遗漏了 `theme === 'system'`。当用户选择「跟随系统」且操作系统为深色时，主进程窗口底色仍被设为浅色，而渲染层后续挂载深色主题，必定导致重载时首帧闪白。
2. **深色主题下关键元素可读**：**存疑**。`src/renderer/index.html` 中 `html` 的背景色样式仅依赖 `@media (prefers-color-scheme: dark)`，未像 `#boot-splash` 那样提供基于 `html[data-theme]` 的覆盖规则。在「用户浅色+系统深色」等冲突场景下，`html` 底色将脱离用户设置，出现黑底/白底错位。
3. **封面九题材渲染**：**无法判定**。diff 截断，核心封面文件 `coverArt.ts` 和 `BookCover.vue` 未包含在代码变更中。
4. **字体本地加载成功**：**无法判定**。仅有 woff2 二进制文件入库，未见 `@font-face` 声明及字体栈修改的 diff。
5. **品牌资产**：**存疑**。启动画面移除逻辑在材料中自相矛盾：附录 A4 声称已改用首帧信号驱动（nextTick+rAF+600ms超时），但作为源码事实的附录 B 仍为 `setTimeout 60ms` 旧逻辑。
6. **焦点环/滚动条/输入框边框令牌生效**：**存疑**。组件 diff 显示输入框保留了 `outline-none focus:border-ink-primary`，若全局 `:focus-visible` 按声明注入了 `box-shadow` 焦点环，二者叠加会产生双重焦点指示器。
7. **typecheck 三重闸门 + console 零报错 + 零 AI**：**无法判定**。静态审查无法验证运行时零报错。

## 发现的问题
1. **严重 - `system` 主题模式防闪白逻辑失效**：
   - 位置：`src/main/index.ts` 
   - 缺陷：`darkPredicted = theme === 'dark' || (theme === '' && nativeTheme.shouldUseDarkColors)` 遗漏了 `theme === 'system'`。当 `ui.theme` 存储值为 `'system'` 时，`darkPredicted` 必定为 `false`，导致 `BrowserWindow` 强制使用浅色底色。
   - 修复建议：改为 `theme === 'dark' || ((theme === '' || theme === 'system') && nativeTheme.shouldUseDarkColors)`。

2. **严重 - `html` 背景色未响应 `data-theme` 属性**：
   - 位置：`src/renderer/index.html` `<style>` 标签
   - 缺陷：`html` 背景色仅写了基础规则和 `@media (prefers-color-scheme: dark)` 规则，没有针对 `html[data-theme='light']` 和 `html[data-theme='dark']` 的显式覆盖（而紧随其后的 `#boot-splash` 样式已正确添加了该覆盖）。当内联脚本将 `data-theme` 设为与系统偏好相反的值时，`@media` 规则依然生效，导致页面底层背景与 splash/应用主题色割裂。
   - 修复建议：补充 `html[data-theme='light'] { background: #faf8f3; }` 及 `html[data-theme='dark'] { background: #171512; }`，利用更高优先级覆盖 media 查询。

3. **中等 - 输入框双重焦点指示器冲突**：
   - 位置：`ApiProfileDialog.vue` 等多处组件
   - 缺陷：输入框保留了 `outline-none focus:border-ink-primary`，而根据验收材料，全局 `theme.css` 已通过 `:focus-visible` 添加了 `box-shadow` 焦点环。`outline:none` 仅移除 outline，不影响 box-shadow，这将导致聚焦时同时出现边框变色和焦点环阴影，产生冗余视觉反馈。
   - 修复建议：对于自定义 `focus:border` 的组件，应补加 `focus-visible:shadow-none`（或等效类）以屏蔽全局焦点环。

4. **中等 - 启动画面退场逻辑材料自相矛盾**：
   - 位置：附录 A4 与 附录 B
   - 缺陷：附录 A4 明确记录已采纳「首帧信号驱动（nextTick → rAF → dismiss()，600ms超时）」的整改方案，但附录 B 提供的核心源码事实中，`main.ts` 仍为 `setTimeout(() => {...}, 60)` 的旧逻辑。若以附录 B 为准，则慢机器提前暴露白屏的中危问题尚未真正修复；若以 A4 为准，则材料事实严重失真。
