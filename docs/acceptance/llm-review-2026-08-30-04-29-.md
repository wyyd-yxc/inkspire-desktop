# LLM 审查（MiniMaxAI/MiniMax-M3）

> 材料来源：material-M16-package.md

## 结论

**不通过** — 验收材料在「代码变更 diff」一栏为空，无法证明本次 M16 打包发布产生了实际可审查的代码/配置变更；同时多项验收点仅给出结论性叙述，缺少可直接核对的产物证据与可复现脚本细节。

## 发现的问题

| 级别 | 问题 |
|------|------|
| 🔴 严重 | **「代码变更 diff」为空**。M16 显然至少应包含 `electron-builder.yml`（新增 `npmRebuild:false`、可能还有 `asarUnpack`、`productName`、`icon`、`win.target` 等）、`package.json`（版本号 0.1.0→0.6.0、productName、build 配置）、图标生成脚本、`tmp/icon-preview.png` 与 `tmp/packaged-smoke.mjs` 的新增。**完全没有 diff，等同于无变更可审查**，无法独立确认任何配置项实际写入。 |
| 🟠 高 | **核心断言无可核验凭据**：CDP 烟测、blockmap 存在、native 模块路径、默认档案预设，全部仅以叙述形式给出，缺乏原始输出（终端日志、文件树、`sqlite3` 版本校验输出）。在外部审查标准下，这些应作为附件提供而非概括转述。 |
| 🟠 高 | **「默认档案 GMI Cloud · MiniMax M3」流式对话成功 ≠ 打包可独立运行**。材料自承认 userData 与开发期共享，则该测试仅证明「开发机上的免安装目录可启动」，并未证明「全新 Windows + 安装包 + 默认配置」即可用。此验收点 3 与 5 实际存在循环论证。 |
| 🟡 中 | **`npmRebuild: false` 的安全隐患**（仅在能确认确实如此的前提下）。better-sqlite3 的 NAPI 预编译虽跨 ABI，但版本与 Electron 版本仍需严格匹配；若 `package.json` 中 `better-sqlite3` 版本与 Electron 的 Node ABI 不一致，运行时会 `NODE_MODULE_VERSION` 报错。材料未说明预编译包版本与 Electron 版本对应关系，**需运行验证**。 |
| 🟡 中 | **图标程序化生成未说明版权与多分辨率**：仅写「罗兰紫圆角底 + 白色墨滴」，未说明是否覆盖 16/32/48/64/128/256 多尺寸（Windows 任务栏/资源管理器各 DPI 均会用到），亦未提供 ICO 文件 `pngcheck` 或 `icoinfo` 输出验证含 256×256 PNG。 |
| 🟡 中 | **未代码签名的风险说明含糊**：「用户点『仍要运行』即可」对企业/政企终端通常**不可行**（域控策略可能直接拦截）。M16 作为「开箱即用」交付物，这一已知边界应升级为验收阻塞项而非脚注。 |
| 🟢 低 | **「测试书已删、无残留进程」**属自描述，无 `tasklist /FI "IMAGENAME eq InkSpire.exe"` 输出佐证。 |
| 🟢 低 | **NSIS 安装选项**（非单击版、可选安装目录）未给出 `nsis.oneClick / perMachine / allowToChangeInstallationDirectory` 的实际配置行，无法核对是否真的实现了「非单击」与「可选目录」。 |

## 无法判定项（需运行验证 / 补交材料）

1. **`dist/` 实际文件树**（特别是 blockmap、latest.yml、app.asar.unpacked 内 *.node 路径与文件名）。
2. **`electron-builder.yml` 与 `package.json` 的实际配置内容**——本次 diff 为空，必须补交完整文件或 unified diff。
3. **`tmp/packaged-smoke.mjs` 脚本源码**与最近一次运行的完整 CDP 输出。
4. **`tmp/icon-preview.png` 实际图像**（需目视确认与各 DPI 下的渲染效果）。
5. **better-sqlite3 版本号 × Electron 版本号 × Node ABI** 三者匹配性——只有 `npm rebuild` 失败信息，无对应版本日志。
6. **NSIS 安装器在全新 Windows 虚拟机上的真实行为**（/S 静默、桌面/开始菜单快捷方式、卸载项、控制面板条目）。
7. **Windows SmartScreen 在未签名场景下的实际拦截级别**（开发方降级处理，但实际体验可能严重影响「开箱即用」定位）。
8. **升级路径**：若用户已有 0.1.0–0.5.x 旧版 userData，0.6.0 安装是否做数据迁移？材料完全未涉及。
