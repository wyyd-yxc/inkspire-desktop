## 发现的问题

### 🔴 严重

**#1 userData 共享端到端证据缺失（影响验收点 5）**
材料 D 仅在文字层面论证了"Electron app.getName() 取 inkspire-desktop → 天然共享 %APPDATA%"。这只是一个机制说明，不是**运行时证明**。用户验收要求是"档案已就绪，用户安装后无需重新配置 AI"——需要的是：
- 开发期写入一条书（或一条对话）
- 安装安装包
- 安装包版本读到同一条
这一闭环证据未给出。机制正确≠结果正确（任何一步打包配置错误——如 `productName` 覆盖、`appId` 不同、asarUnpack 漏配——都会破坏共享）。**此项不应被认定为通过**，需补一条烟测：开发版写 → 安装版读。

### 🟡 中等

**#2 烟测脚本未提供（影响验收点 3 的可复核性）**
材料仅展示烟测**输出文本**，未附 `tmp/packaged-smoke.mjs` 源码。审查员无法验证：
- 它是否真的连接了 `InkSpire.exe --remote-debugging-port=9223`（而非连到 dev 版）
- "books.list ok(0 本)"→"created"→"foundInList"→"deleted" 是否真的命中了 SQLite 落盘路径，还是只在内存里 create 又 delete
- AI 流式测试的 prompt 是什么、是否真的经过打包产物的网络栈

`assert`/退出码/`Process.exit` 行为均无法审查。**这是审计可追溯性的硬伤**。

**#3 better-sqlite3 ABI 匹配的"运行时证明"不充分（影响验收点 2）**
材料 D 称"烟测 books.list ok 即运行时证明"。严格说：
- `books.list ok(0 本)` 只证明 `.node` 被 `require` 成功且 `prepare` 成功
- 没有 DDL（建表）、没有真实写入+读取回环、没有复杂查询
- better-sqlite3 在 Windows 上 ABI 不匹配的征兆常在**首次 prepare 含 COLLATE/JSON1/FTS 的语句**时浮现
因此该证据**只覆盖了"加载"，未覆盖"功能完整"**。建议至少补一条 `CREATE TABLE ... INSERT ... SELECT` 回环。

### 🟢 轻微 / 规范

**#4 diff 收集失败——代码层审查完全缺失**
材料给出的 diff 块形如 `(diff 收集失败: bad revision 'v0.5.0..HEAD')`。这意味着审查员**看不到**以下关键变更：
- `electron-builder.yml` 中 `npmRebuild: false` 的位置与上下文（是否同时禁用了 `buildDependenciesFromSource` 等可能触发 node-gyp 的开关）
- `package.json` 中 `name`、`productName`、`version` 字段是否一致
- 是否新增了 `asarUnpack` 配置（better-sqlite3 必须 unpack，否则 `require` 不到 `.node`）
- 应用代码是否有 process.platform / __dirname / path 相关的打包后兼容修改（路径分隔符、`asar` 内文件读取等）
**没有 diff，本次代码层审查的产出为零。** 这本身应被视为交付不完整——验收材料必须包含可审计的代码变更。

**#5 静默安装 / 卸载入口证据缺失（影响验收点 6）**
NSIS `/S` 静默安装是否真的成功（无 UI 卡顿、无 1603/1602 错误码）、安装后的 `InkSpire.exe` 是否真的可双击启动、卸载是否在"添加或删除程序"中存在条目——三项均无截图、无日志、无事件记录。属于"声明而非证据"。

**#6 已知边界中的风险点未做用户告知材料**
- SmartScreen 未签名提示 → 应在 README 或安装包首次运行弹窗中告知用户，材料未说明是否做了用户告知
- 自动更新未引入 → 未来版本升级需用户手动卸载重装，是否在文档中标注？未提及

## 无法判定项（静态审查无法覆盖）

| 类别 | 项 | 原因 |
|---|---|---|
| 运行时 | 全新 Windows VM 上安装包的真实表现 | 开发方声明本机无全新 VM，未做 |
| 运行时 | 安装包 exe 在 Windows SmartScreen 下点击「仍要运行」的实际 UX | 未录屏 |
| 运行时 | better-sqlite3 在打包后执行 INSERT/SELECT 真实落盘的字节内容 | 烟测仅覆盖 SELECT 空表 |
| 运行时 | NSIS 安装包在 Win10/Win11 不同版本下的兼容性矩阵 | 未声明测试矩阵 |
| 性能 | 安装包冷启动时间、内存占用 | 未提供 |
| 安全 | `app.asar.unpacked` 之外是否还有其它必须 unpack 但被遗漏的原生依赖 | diff 缺失，无法静态确认 |
| 代码 | `electron-builder.yml` 完整最终内容 | diff 缺失 |
| 代码 | package.json 中 `appId` 是否与开发期一致（影响 Windows 注册表 userData 路径） | diff 缺失 |

## 给开发方的补正清单（按优先级）

1. **(必须)** 提供 `tmp/packaged-smoke.mjs` 完整源码，附其在 9223 端口的 `targets` 配置
2. **(必须)** 提供 dev 版写入 → 安装版读出的端到端证据（验收点 5 闭环）
3. **(必须)** 提供真实的 git diff（tag 命名不规范或工作区不干净需先修复）
4. **(必须)** 补一条 SQL 回环烟测：建表→插入→查询→清理
5. **(建议)** 静默安装/卸载各附一条带时间戳的执行日志
6. **(建议)** 提供 `electron-builder.yml` 与 `package.json` 最终内容的关键字段（`appId`、`productName`、`asarUnpack`、`files`、`npmRebuild`）

——

**审查员签注**：材料在"交付物清单"与"问题自述"两个维度做得较充分（开发方对失败原因、镜像、ABI 边界都有清晰交代），但在"可审计证据"维度——尤其是烟测源码、端到端 userData 共享、diff 完整性——存在系统性缺口。建议开发方补齐上述四项"必须"项后即可放行。
