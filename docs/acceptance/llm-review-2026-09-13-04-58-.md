# LLM 审查（glm-5.1）

> 材料来源：material-M15.5-relayout.md

## 结论

**有条件通过** —— 壳布局核心骨架与切章保存归属章重构逻辑自洽，AI面板密封/缓冲及Toast/Digest技术债清偿代码实锤闭环；但提交代码严重截断导致关键页面变更黑盒化，且存在删除键焦点样式遗漏、面板卸载缓冲区丢失等规范违背与卫生问题，需补全代码并修复后复验。

| 验收点 | 判定 | 核对说明 |

| 3. 助手浮球/同步按钮书内全局 | **可判定** | `BookShellLayout.vue` 摘录证实 `AssistantDock` 与 Sync 组件随壳挂载，`editorCtx` 经 provide 跨页传递，逻辑成立。 |
| 4. 章节树 CRUD + 场景画布壳保持 | **可判定** | `ChapterSidebar.vue` diff 证实瘦身为纯树并保留 CRUD emit，画布跳转依赖 `bookId` prop（r1已自证），壳保持由路由嵌套保证。 |
| 5. 技术债回归（删除键/Toast DOM/拆书提示） | **可判定** | `BookCard.vue` 常驻显式、`ToastHost.vue` 离场截断、`StyleDigestDialog.vue` 消息分级与截断提示代码均可见且符合预期。 |
| 6. 书房/设置不套壳 + redirect + 闸门 | **部分可判定** | 路由摘录证实嵌套与 redirect；typecheck 闸门经 r1 披露对 `.vue` SFC 实质失效（vue-tsc 不兼容 TS7），仅靠转译与运行时兜底，静态类型安全有缺口。 |

## 发现的问题

| 严重级别 | 问题 | 定性与说明 |
|---|---|---|
| **高** | 关键页面 diff 截断，验收材料不完整 | 除 `ChapterSidebar` 外，Genesis/Canvas/Plot/Wiki/Memory/Inspirations/Stats 七页去旧返回栏的代码变更完全缺失；`WorkspaceView.vue` 切章保存核心也仅有摘录。无法静态验证「全站 grep 清零」及保存时序的完备性，需补全 diff。 |
| **中** | `BookCard.vue` 删除键遗漏 `focus` 危险色样式 | 验收声明要求「hover/focus 加深为危险色」，代码添加了 `hover:bg-ink-danger` 但**缺失 `focus:bg-ink-danger focus:text-white`**。键盘聚焦时按钮仅变全透（`opacity-100`）但仍为灰底，触屏/键盘可达性不达标，违背无障碍规范。 |
| **中** | `AiWritingPanel.vue` 卸载未刷新流式缓冲区 | `onBeforeUnmount` 仅清理定时器（`clearTimeout`），未调用 `flushBuf()` 将 `buf` 中已到但未上屏的增量刷入 `text.value`。若组件在流式输出中被强卸，在途数据静默丢失。虽属展示层，但若父组件有状态恢复预期则构成隐患。 |
| **低** | `ChapterEditor.vue` 停止生成时 `seal()` 与 `finish()` 冗余调用 | `stopGeneration` 中先调 `seal()` 再调 `finish()`，而 `finish()` 内部已包含 `flushBuf()+sealed=true` 全部逻辑，`seal()` 属多余调用。不影响功能但增加理解成本。 |
| **信息** | typecheck 闸门对 `.vue` 文件失效 | r1 已披露 `vue-tsc` 与 TS7 不兼容，导致 `.vue` SFC 内的类型错误（如未导入标识符）无法在编译期拦截，依赖运行时炸裂才发现。此为既有工程缺口，非本轮引入，但影响全局质量信心。 |

## 无法判定项

1. **六页去头部完整实现**：Genesis/Canvas/Plot/Wiki/Memory/Inspirations/Stats 的旧返回栏、头部块是否彻底移除，路由高亮是否正确配置（需补全 diff 或运行时全页遍历验证）。
2. **壳数据加载与内存管理**：`BookShellLayout.vue` diff 截断处可见 `wikiEntries` 等数据 ref，壳组件是否加载过重、是否在切书时正确释放内存（需完整代码审查或运行时性能剖析）。
3. **切章保存边界时序**：`onBeforeUnmount` 兜底落盘在组件树卸载过程中的执行时序是否绝对早于路由参数丢失，极端快速切章是否仍可靠（需 CDP 驱动的 T3b 高频切章测试验证）。
4. **Toast DOM 4s 清理**：`display:none` 修复依赖 Vue Transition 在无 `transition` 属性时的同步/近同步卸载策略，在极低性能设备或特殊 Electron 窗口状态下是否严格 <4s（需运行时实测）。
