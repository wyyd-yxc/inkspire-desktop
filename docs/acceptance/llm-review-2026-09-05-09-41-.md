## 发现的问题

### 🔴 严重

**#1 DAO「同向重复」校验逻辑漏洞 — 可能导致用户能绕过限制**
- 位置：`main/db/sceneEdges.ts` `createSceneEdge`
- 代码查的是 `(source_id, target_id, type)` 三元组，但 Vue 端 `onConnect` 调用时**未传 type**，落库默认 `'main'`。
- 结果：用户先建 main 边 A→B，再想建 relation 边 A→B（语义上完全合理："A 因果导致 B，且 A 与 B 主题关联"）会被**误拒**为重复。
- 验收材料第 1 点写的是「同向**同类型**重复」，但当前实现连"同向不同类型"也一并挡了。
- 修复建议：①DAO 改为查 `(source_id, target_id)`（任何类型都视为同向重复）；②或在 DAO 仍按类型查，但加 `type` 索引提示给用户更明确的错误。

**#2 关系方向描述与验收材料自相矛盾 — 因果可能被写反**
- 验收材料第 5 点自测声明：「relationText 注入无报错」、宣称「因果不写反」。
- 实际代码 `relationTextFor`：
  ```
  if (e.sourceId === scene.id) {
      e.type === 'logic' ? '因果指向' : ...
  }
  ```
- 含义：若当前场景是 **source**，关系是 `logic`，则说"本场景因果指向 target"。
- 但在 `scene_edges` 表里，`source`/`target` 仅是 Vue Flow 的连线方向，**用户在画布上连线时拖出方向随意**，并没有强制约定"原因→target"。
- 这意味着：用户拖了一条 A→B 的 logic 边给系统，prompt 注入「**A 因果指向 B**」；但若用户实际意图是 B 导致 A，模型就会被误导生成反向因果。
- 修复建议：①建边时强制"原因→结果"的方向校验或提示；②或在编辑侧允许用户切换 source/target 语义；③最少应在 `createSceneEdge` 拒绝反向同类型重复（当前 SQL 也没做）。

### 🟡 中等

**#3 IPC handler 无参数校验/类型守卫**
- 位置：`main/ipc/sceneEdges.ts`
- `scene-edges:create` 直接把 `input` 透传给 DAO，依赖 DAO 内部 `throw`。Renderer 端会收到 `IpcResult.ok=false` 的错误字符串，但**没有 schema 校验**。
- 风险：若 renderer 被 XSS/供应链污染，可注入 `chapterId` 指向**任意章节**（跨章节越权建边）；当前场景仅信任前端传入。
- 建议：用 zod 或类似最小校验 `chapterId/sourceId/targetId` 为合法 UUID。

**#4 Renderer 端未做去重的乐观更新**
- `onConnect`：`sceneEdges.value.push(res.data)` 直接追加。
- 风险：若用户快速拖两次或 IPC 重试，会出现重复边。
- 建议：push 前先 `findIndex` 去重。

**#5 编辑器 Save/Remove 缺幂等保护**
- `saveEdgeEdit` 未禁用按钮，连点会触发多次 update；`removeSelectedEdge` 同样。
- 建议：操作期间加 `isSavingEdge` 标志。

### 🟢 轻微

**#6 relationText 文案「承接自」对 main/relation 类型也用同一套表述**
- 位置：`relationTextFor`
- `e.sourceId === scene.id` 分支下 main → "顺承接续"、relation → "关联"，语义可接受；但 `e.targetId === scene.id` 分支不分类型一律 "承接自"，丢失了类型信息。
- 模型拿到的提示会丢失类型上下文，可能影响"不写反"承诺。

**#7 边编辑工具栏的取消/失焦关闭未呈现**
- diff 截断处未显示编辑器关闭逻辑，无法判定是否有 ESC/外部点击关闭 — 列入"无法判定"。

**#8 `JSON.parse(JSON.stringify(...))` 多余**
- `saveEdgeEdit` 中 `JSON.parse(JSON.stringify(...))` 仅是为了"脱 Vue 响应式"，但 IPC 已经 `ipcRenderer.invoke` 序列化一次；纯属冗余开销，可读性也下降。

## 无法判定项（需运行验证）

1. **验收点 6 持久化**：迁移 v7 是否对**已有数据库**安全升级（无 `DROP` 应安全，但需运行 `database_exists` 场景验证）。
2. **验收点 5 因果方向**：依赖 LLM 遵循度，开发方已自承"黑盒可抽查" — 无法静态断言模型输出方向正确。
3. **级联删除真实路径**：FK ON DELETE CASCADE 静态正确，但 SQLite `foreign_keys = ON` 是否在每次连接都启用？需运行验证 `PRAGMA foreign_keys`。
4. **Vue Flow 边样式渲染**：`smoothstep` + dasharray 是否在最新版 @vue-flow/core 正常显示虚线（已知部分版本边样式优先级问题）。
5. **删除场景时本地同步时机**：先 `scenes.value.filter` 再 `reorderByX`，但 Vue Flow 节点删除与 setEdges 同步性需运行时确认。
6. **编辑器工具栏关闭/失焦交互**：diff 截断处未呈现。
8. **「节点左右手柄」实现**：diff 中 import 了 `Handle, Position`，但节点模板修改（左右 Handle 区分）部分**未截断可见**，仅可见 import 声明，无法判定左右 Handle 是否真的实现。
9. **`Vue Flow 默认 Delete 键删除行为**未额外定制**"这条已知边界**本身需要运行验证是否真的会导致误删（Vue Flow 默认是删除节点，边的删除需选中边时按 Backspace）。
