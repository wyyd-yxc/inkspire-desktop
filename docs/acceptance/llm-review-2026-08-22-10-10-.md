# LLM 审查（deepseek-v4-pro）

> 材料来源：material-M4-ai-writing.md

## 结论
**有条件通过** — 核心交互流程已构建，但代码中存在两处严重逻辑缺陷（并发竞态、划词采纳位置失效），需修复后重新验证；上下文截断与整章润色采纳未提供足够证据，视为未完成。

## 逐项核对

### 1. AI 续写
- **材料**：状态栏按钮「✦ AI 续写」→ 面板流式预览 → 「采纳插入」追加到文末 → 自动保存落库（声明依赖父组件防抖保存链路）；生成中可停止、可重写。
- **核对**：
  - 按钮、面板、流式推进（`append`/`finish`）、采纳（`focus('end').insertContent`）均在代码中实现。
  - 停止按钮调用 `stopGeneration`，`activeSession.abort()` 可中止流。
  - 重写按钮调用 `retryGeneration` → 重新发起同类型生成。
  - 自动保存：`acceptGeneration` 触发 `editor.onUpdate` → emit `content-change`，但父组件保存逻辑未在本次变更中提供，无法静态确认落库行为。
- **判定**：界面与交互逻辑满足，但自动保存的最终落库依赖外部链路，材料不充分，需运行验证。

### 2. 划词操作
- **材料**：选中文字 → 浮条（润色/扩写/改写）→ 流式生成 → 采纳后仅替换选区，选区外不变。
- **核对**：
  - 浮条定位、按钮、`startSelectionAction` 发起生成、`acceptGeneration` 使用 `deleteRange` + `insertContentAt` 替换选区，意图正确。
  - **严重缺陷**：采纳时直接使用生成前保存的 `selectionTarget`（`from`/`to`），未检查当前选区是否仍与该快照一致。若用户在生成期间移动光标或编辑了文档，采纳将替换错误位置，破坏文档结构。
  - 浮条定位计算（`coordsAtPos` 与容器 `getBoundingClientRect` 相减）**未考虑编辑器滚动偏移**，当文档较长、选区不在可视区域顶部时，浮条可能错位或不可见。
- **判定**：核心逻辑存在缺陷，无法保证“仅替换选区”的正确性，需修复。

### 3. 整章润色
- **材料**：标题栏「✧ 整章润色」→ 流式生成（正文不被中途改动）→ 采纳后整章替换。
- **核对**：
  - 按钮入口、`runGeneration('chapter-polish')`、`acceptGeneration` 分支 `ed.commands.setContent(text)` 均存在。
  - 生成过程中未修改编辑器内容，符合“正文不被中途改动”。
  - 开发自测声明 **明确表示整章润色未单独实测**，仅依赖与划词共用的管线，未验证采纳行为的正确性。
- **判定**：代码结构完整，但缺少实际测试结果，材料不足以证明其达成。

### 4. 上下文
- **材料**：提示词包含书名/题材/简介 + 章节标题 + 前文尾部（截断至 3000 字）；system 约束输出纯正文。
- **核对**：
  - `writingContext()` 仅返回 `book`、`chapterTitle`、`contextTail`（`editor.getText()`），**无截断逻辑**。
  - 提示词构造函数 `build*Messages` 在 `src/renderer/src/services/aiWriting.ts` 中，该文件未在 diff 中提供，无法验证是否实施了截断或 system 约束。
- **判定**：关键实现缺失，无法判定上下文构造是否符合要求。

### 5. 并发与中断
- **材料**：生成中锁 busy（重复点击被拦）；停止/关闭面板/切换章节/组件卸载均正确中止。
- **核对**：
  - `busy` 锁在 `runGeneration` 开头检查，阻止重复生成。
  - **严重缺陷**：`runGeneration` 先设 `busy = true`，再通过 `nextTick` 异步执行，而 `stopGeneration` 同步设置 `busy = false` 并试图中止。若用户快速点击“续写”再立即点击“停止”，`stopGeneration` 将在 `nextTick` 回调之前执行，`busy` 被重置，但 `runGeneration` 的异步部分仍会继续调用 `generateWriting`，导致生成被意外启动，且 `busy` 已为 `false`，可能允许再次生成，造成并发混乱。
  - 关闭面板、组件卸载均调用 `stopGeneration`，可中止流，但上述竞态问题同样影响这些场景。
- **判定**：并发控制存在竞态缺陷，不能满足“正确中止”的要求。

### 6. 持久化
- **材料**：采纳后经自动保存链路（防抖 1.5s/Ctrl+S/切章 flush）落库，重启保留。
- **核对**：
  - `ChapterEditor` 仅通过 `emit('content-change')` 向外传递变更，未包含任何持久化逻辑。
  - 父组件、防抖、切章 flush 等实现均未在本次变更中提供，无法验证。
- **判定**：材料不足，无法判定。
