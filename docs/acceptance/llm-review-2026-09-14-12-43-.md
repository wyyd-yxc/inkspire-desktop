# LLM 审查（glm-5.1）

> 材料来源：material-M17-visual.md

## 结论

有条件通过 —— 主题注入链架构正确、对比度验算与品牌资产材料充分，但 index.html 内联主题脚本存在「用户选浅色+系统深色时启动画面主题错乱」的可判定缺陷，且核心文件（theme.css/useTheme.ts/coverArt.ts/BookCover.vue/AppearanceSection.vue）diff 缺失导致多项验收点无法静态闭合。

## 发现的问题

### P1（严重）：内联主题脚本未设置 `data-theme="light"`，导致「用户选浅色 + 系统深色」场景启动画面主题错乱

**位置**：`src/renderer/index.html` 内联 `<script>`

**缺陷**：
```js
var dark = injected === 'dark' ||
  (injected !== 'light' && (injected === 'system' || !injected) &&
   window.matchMedia('(prefers-color-scheme: dark)').matches)
if (dark) document.documentElement.setAttribute('data-theme', 'dark')
// ← 缺少 else 分支：setAttribute('data-theme', 'light')
```

当 `injected === 'light'` 且 OS 为深色时：
- `dark` 计算为 `false`，`data-theme` **不被设置**
- `@media (prefers-color-scheme: dark)` 命中 → splash 以深色渲染（底色 `#171512`、logo 暖白）
- `html[data-theme='light'] #boot-splash` 选择器不匹配（因为属性不存在）
- **结果：用户明确选了浅色，启动画面却显示深色**，直至 splash 移除

同理，`<head>` 中 `html { background: #faf8f3; }` 的 `@media (prefers-color-scheme: dark)` 覆盖也存在同样问题——`data-theme` 不为 `'light'` 时深色底色生效，首帧即错。

**修复**：补 `else` 分支显式挂载 `data-theme="light"`：
```js
if (dark) document.documentElement.setAttribute('data-theme', 'dark')
else document.documentElement.setAttribute('data-theme', 'light')
```

### P2（中等）：`void initTheme()` 丢弃异步错误

**位置**：`src/renderer/src/App.vue`

```ts
onMounted(() => {
  void initTheme()  // void 吞掉 Promise rejection
  startAutoSync()
})
```

若 `initTheme()` 内部读库/写库失败（如 settings IPC 异常），reject 会被静默吞掉，用户无任何反馈且主题可能未初始化。应至少 `.catch(console.error)` 或用 toast 通知。

### P3（低）：brand.ts 模板字面量注入颜色值无校验

**位置**：`src/renderer/src/assets/brand.ts`

```ts
export function logoSvgBody(ink = '#3a352e', seal = '#a8443a'): string {
  return [
    `<rect ... stroke="${ink}" .../>`,
    `<path ... fill="${ink}"/>`,
    `<circle ... fill="${seal}"/>`
  ].join('')
}
```

参数直接拼入 SVG 字符串。当前调用方均为硬编码常量，无安全风险；但若将来任何路径接受外部输入（如用户自定义品牌色），即构成 XSS 注入面。建议对参数做正则白名单校验 `/^#[0-9a-fA-F]{6}$/`。

### P4（低）：CSP `script-src` hash 与内联脚本强耦合

**位置**：`src/renderer/index.html` CSP meta

```
script-src 'self' 'sha256-o+8CBGRwfeL1jtiXNcqF9UPIAvRF0DVkqYg9oInMvnI='
```

原 CSP 无 `script-src`（走 `default-src 'self'`）。新增后，内联脚本任何字符变动（含空格、换行、注释）都会导致 hash 失效、脚本被 CSP 拦截、主题初始化整体失效。**无自动化校验机制**（如构建期 hash 重算），属于易踩坑的手动维护点。

### P5（低）：`<select>` 元素 `bg-surface` 跨平台一致性

**位置**：`ApiProfileDialog.vue` 多处

```html
<select class="... bg-surface ...">
```

原生 `<select>` 在部分 Chromium 版本/OS 组合下 `background` 样式不完整穿透（下拉选项面板仍用系统色）。Electron 内通常可接受，但若深色模式下下拉选项列表仍为白底，会造成可读性问题。需运行验证。
