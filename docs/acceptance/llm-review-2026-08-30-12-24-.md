## 发现的问题

### 🔴 严重（安全/正确性）
1. **SQL 迁移缺少幂等降级保护 / 字段命名不一致风险（次要）**  
   `scenes.ts` 中 `tension` 列声明 `INTEGER NOT NULL DEFAULT 3`，但 `CreateSceneInput.tension` 默认 `3`、`UpdateSceneInput` 中 clamp 为 1–5；前端类型若允许 `undefined` 直传 `null`，better-sqlite3 会以字面 `null` 写入导致 NOT NULL 违例——属于"边界未防御"。建议在 DAO 层 `Number(x) || 3`。
2. **`parseJson` 静默吞错**  
   `scenes.ts:28-34` JSON 字段解析失败仅 `console.warn` + 回退空数组。**tags/wikiRefs 损坏将导致用户编辑数据"看似成功"但落库丢失**，无 UI 反馈、无修复入口。建议至少在 IPC 层返回部分失败标记或触发重读+提示。
3. **`removeScene` 序号压缩写错条件**  
   `WHERE chapter_id = ? AND sort_order > ?` 删除后应将**大于被删 sort_order** 的行 `-1`，看似正确；但 `createScene` 默认 `sort_order = count+1`、又允许外部传 `input.sortOrder` 覆盖——若插入指定 `sortOrder=5`，当前 count=3 会与现有 3/4 冲突，**无 UNIQUE 约束、无 REORDER**，将造成重复 sort_order 直接破坏 `listScenes` 顺序。建议迁移补 `UNIQUE(chapter_id, sort_order)` 或事务内整体 renumber。
4. **`reorderScenes` 缺少存在性校验**  
   若传入的 `orderedIds` 包含不属于该 chapter 的 id 或有遗漏，UPDATE 仅影响子集，**剩余行 sort_order 保持旧值**，导致画面与数据库顺序错位。建议在事务内先校验 `count(matching rows) == orderedIds.length`。

### 🟡 中（规范/可维护性）
5. **`updated_at` 列命名不一致**  
   `database.ts` migration v6 字段名是 `created_at`/`updated_at`，DAO 内部 row key 也是 `created_at`/`updated_at`（一致），但 `WikiEntry`/其他表可能用 `createdAt`/`updatedAt` 风格——需确认其他 DAO 是否也存在混用，迁移补注释说明命名约定。
6. **IPC handler 未做 channel 白名单与参数类型守卫**  
   `ipc/scenes.ts` 直接 `wrap(() => ...)`，未校验 `input` 结构；若 renderer 侧 TS 绕开可传任意对象，存在脏数据风险。属架构级问题（非本 PR 引入），但本 PR 沿用旧模式，建议在 wrap 层加 zod/手写守卫。
7. **preload 暴露面增加未在文档登记**  
   `api.scenes.*` 五通道未在 `shared/canvas.types.ts` 摘要中标注 IPC 命名（虽代码可见），交付物应附 IPC 契约表。
8. **`ChapterSidebar.vue` 的 hover 操作按钮缺 `aria-label`**  
   仅有 `title` 属性，无障碍不达标；与既有按钮一致（本 PR 未引入恶化，但本就是欠账）。
9. **`scenePrompts.ts` 截断**  
   仅有 80 行可见（206 行声明），**五模式 user prompt 拼装函数、宽容 JSON 解析、正则救援均不可见**。审查员无法证实"严格 JSON + 宽容 + 正则救援"三道防线真实存在。

### 🟢 低（提示）
10. 自测声明 "AI init 流式实测 997 字"——未附日志/截屏，仅文字声明，无法验证。
11. `package.json` 仅声明 `@vue-flow/core` 与 `background`，**未声明 `@vue-flow/controls`、`@vue-flow/minimap`**——若 CanvasView 使用这些子包，依赖缺失；需以最终 lockfile 复核。
12. "连线仅视觉存储（生成顺序由 x 坐标决定）"在 v1 是合理简化，但**验收点 2 写"按 x 重排 sort_order"**——代码侧未见 `CanvasView` 中 `nodeDragStop → reorderScenes` 的实现，材料不足以证实。
