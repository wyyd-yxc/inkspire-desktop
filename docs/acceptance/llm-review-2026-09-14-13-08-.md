## 发现的问题

### 1. [中危] `brand.ts` 硬编码色值与「currentColor 随主题」声明冲突
- **位置**：`src/renderer/src/assets/brand.ts` + 验收材料「品牌资产」章节
- **现状**：`logoSvgBody` 默认参数为 `ink = '#3a352e'`，生成的 SVG 包含内联属性 `stroke="#3a352e"`。验收材料声称「书房顶栏：挂 SVG 标识（currentColor 随主题）」。
- **风险**：SVG 内联呈现属性优先级高于 CSS `currentColor` 规则。若顶栏组件调用 `logoSvgBody()` 时未显式传入 `ink='currentColor'`，深色模式下顶栏 Logo 将保持深色（#3a352e）导致隐形；若传入，则 `brand.ts` 的默认参数即为无效设计，且破坏了 SVG 作为纯结构资产的纯净性。
- **建议**：`brand.ts` 应剥离颜色参数，统一使用 `currentColor`，由父级 CSS 控制主题色；或在调用侧严格校验传参。

### 2. [低危] Preload 冗余防御代码
- **位置**：`src/preload/index.ts`
- **代码**：`themeArg.split('=')[1] ?? 'light'`
- **分析**：当主进程注入 `--inkspire-theme=`（空串）时，`split('=')[1]` 返回空串 `''`。空串不是 Nullish 值，`?? 'light'` 不会触发。此逻辑当前能正确工作（空串回落系统偏好），但 `?? 'light'` 属于永不可达的死代码，易引发后续维护者误解（误以为默认回退浅色）。
- **建议**：移除 `?? 'light'` 或改用 `|| 'light'`（若意图是空串也回退浅色，但这与「灭 FOUC」的空串=系统逻辑矛盾）。

### 3. [规范] 关键 diff 缺失破坏静态审查闭环
- **现状**：`src/renderer/src/main.ts`（Splash 移除核心逻辑）、`theme.css`（令牌定义）、`useTheme.ts`（三模式逻辑）均不在 diff 中，仅能依赖附录 B 的文本摘录。
- **风险**：文本摘录无法证明代码实体已提交且与 diff 基线一致，且存在前轮审查中「附录代码与实际 diff 不一致」的先例（附录 A6）。

## 无法判定项

1. **Top Bar Logo 实际渲染**：是否按声明使用 `currentColor`，深色模式是否可见。
2. **`theme.css` 令牌体系**：三层架构完整性、`:focus-visible` 焦点环/滚动条样式是否生效、`@font-face` 声明是否存在。
3. **封面系统**：`coverArt.ts` 九题材 SVG 底纹与排版策略的代码实现。
4. **CSP Hash 匹配**：`index.html` 内联脚本内容与 CSP `sha256-...` 是否一致（脚本修改需重算 Hash）。
5. **运行时稳定性**：系统主题动态切换时窗口底色是否跟进（当前 `backgroundColor` 仅在创建时确定）、慢机首帧 Splash 退场时机、深色对比度 19 项是否真 PASS。
6. **Typecheck 与零 AI**：三重闸门通过情况。
