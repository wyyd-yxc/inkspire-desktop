# LLM 审查（glm-5.1）

> 材料来源：material-M15-bindings.md

## 结论
有条件通过（核心逻辑严密、静态代码无明显缺陷，但 diff 截断致使部分调用点改造无法全量验证，且运行时路由断言需黑盒实证）

## 逐项核对
1. **两档案不同模型时，各槽位请求路由到各自绑定档案**
   - **可判定**：`resolveProfileForSlot`（附录 B）实现槽位绑定优先（`bindRes.data.find`），命中则返回对应档案，逻辑无误。
   - **疑点**：diff 在 `useAutoSync.ts:395` 处截断，无法静态核对全部 14 个调用点是否均正确传参。虽然 `generateWriting` 签名强制必传 `slot` 是有效的编译期保障，但截断导致归槽完备性不能 100% 静态确认。
2. **未绑定槽位回落默认；`bindings:set(slot,'')` 删绑定回落**
   - **可判定**：`bindings.ts` 中 `if (profileId === '')` 执行 `DELETE` 语句；`resolveProfileForSlot` 中未命中绑定档案时回落 `defRes.data`，再回落 `profiles[0]`。逻辑严格符合验收点。
3. **删除档案后对应槽位绑定级联清零、回落默认不报错**
   - **可判定**：Migration v15 建表 SQL 包含 `profile_id TEXT NOT NULL REFERENCES api_profiles(id) ON DELETE CASCADE`。
   - **疑点**：`foreign_keys = ON` 的运行状态在 diff 中不可见（材料称在 `database.ts getDb` 既有），且 SQLite 需编译时开启该特性，静态无法确证。
4. **绑定重启持久**
   - **无法判定**：数据落盘逻辑（better-sqlite3 同步写入）无误，但持久性跨重启验证属运行时行为。
5. **设置分区 8 行渲染+即改即存**
   - **可判定**：`SlotBindingsSection.vue` 使用 `v-for="slot in AGENT_SLOTS"` 渲染固定 8 行；`onPick` 调用 `window.api.bindings.set` 即时入库；`:disabled="saving !== ''"` 防重复提交；catch 块 `await load()` 回拉真实状态防 DOM 割裂。代码完全符合验收要求。
6. **typecheck 三重闸门+console 零报错+自测零外部 AI 消耗**
   - **无法判定**：属运行时测试声明，静态审查不可见。

## 发现的问题
- **中危（材料疑点）**：**diff 截断导致归槽清单不可静态复核**
  - `useAutoSync.ts`、`useMemorySync.ts` 等多处 composable 的调用点 diff 被截断。材料附录 A2 给出了 14 个调用点清单并声明依赖必传参数，逻辑上成立，但作为外部审查员无法通过给定 diff 静态确证“无遗漏”。若某个调用点误用未传入 `slot` 的旧重载或绕过 `generateWriting` 直调 `chatStream`，将导致类型系统无法拦截的错槽。
- **低危**：**IPC 边界类型退化为运行时校验依赖**
  - `bindings.ts` 中 `ipcMain.handle('bindings:set', (_e, slot: AgentSlot, profileId: string) => ...)`，跨进程 IPC 序列化会使 `slot` 退化为普通 `string`。虽然代码通过 `AGENT_SLOTS.includes(slot)` 白名单兜底，但类型标注 `AgentSlot` 在 IPC 边界具有误导性（r3 裁定不采纳此意见，但作为外部审查员仍需指出此为项目级规范隐患）。
- **低危**：**`toBinding` 中的不安全类型断言**
  - `bindings.ts` 中 `return { slot: r.slot as AgentSlot, ... }` 直接断言。因写入受白名单严格限制，数据库不会出现非法 slot 值，但断言本身绕过了类型安全，若未来 DB 被外部工具篡改可能将非法值传入前端。

## 无法判定项
- **各槽位请求路由的真实性（T1-T6 路由断言）**：依赖本地假 OpenAI 服务器拦截请求，属黑盒运行时实证。
- **FK CASCADE 运行状态（T8 级联断言）**：依赖 SQLite `foreign_keys` pragma 是否真实生效及 SQLite 编译选项。
- **调用点归槽完备性**：diff 截断无法全量静态核对 14 个调用点，必传参数虽为逻辑保障，但无法排除绕过 `generateWriting` 直调 `chatStream` 的潜在遗漏。
- **重启持久、typecheck 三重闸门绿、console 零报错、外部 AI 消耗 0**：均属运行时验证范畴。
