## 发现的问题

### 【P1-安全/一致性】`plot:create` 与 `plot:update` 未校验事件引用与跨书归属

`createPlotEvent` 接受 `bookId` 但不校验新建事件的 `wikiRefs` 是否真的属于该书；恶意/误操作的渲染端可传入**任意 book 的词条 id** 挂在事件上，导致百科上下文注入错乱。同样，`createPlotEdge` 校验了 UUID 但未校验 `sourceId/targetId` 是否真的属于 `input.bookId`，存在跨书"借边"挂线的可能（虽然 `listPlotEdges(bookId)` 按 book 过滤，前端看不到，但 DB 里会出现悬挂行）。

材料中"无法判定 7（跨书归属）"的回应是"UUID 随机不可枚举 + 单机单用户信任边界，不单域加验"。这是合理的项目约束，但应在 `assertWikiRefs` 旁边显式注释登记，避免后续误以为有校验。

### 【P2-设计边界】延伸落位避让仅看锚点右侧 1 排，未递归扫描多行

`freeRowYAfter` 只判断 `anchor.posY` 同排（±120px）右侧是否有占用，若用户连续延伸两次且锚点不同，会出现"锚点 A 在 y=240 已延伸至 y=240 的右侧；再以锚点 B（也在 y=240）延伸时仅判断 B 的右侧，恰好 B 右侧空，铺到 y=240 → 与 A 的延伸链在 y=240 同行重叠"。

虽然 `adoptDirection` 的多行下移（最多 5 行）覆盖了分歧场景，但**`extend` 模式仅做 1 行避让是不对称设计**。建议补"同 y 行已有节点计数"判断或在落库后再做一次局部冲突扫描。

### 【P2-状态机】`stopEverything` 释放 `isBusy` 会破坏 `AiWritingPanel` 关闭链路

```ts
function stopEverything(): void {
  activeSession?.abort()       // 触发 onError → aiPanel.fail()
  isBusy.value = false         // 立即释放
}
```

中止走 `onError` → `aiPanel.fail()` 是预期的非错误路径，但**同步立刻 `isBusy=false`**会让面板 fail 回调完成前 `isBusy` 已可重入——理论上用户在 fail 动画期间点重试按钮可能进入新的 `startPlotGen`。建议要么把 `isBusy=false` 放到 `onDone/onError` 内部，要么在面板 `@close` 时才释放。

### 【P2-UX 边界】空 desc 的事件在延伸 chain 上下文中被截断到只剩标题占位

`chainFor` 中描述 `e.description.slice(0, 80)`，但若用户大量新建仅标题无描述的事件作为"占位骨架"，`buildPlotExtendMessages` 给 AI 的上下文会一片 `- 标题：<无描述>`，AI 缺乏因果链依据。属 UX 边界，不算缺陷但应在帮助文档中提示"延伸前请给选中事件补全描述"。
