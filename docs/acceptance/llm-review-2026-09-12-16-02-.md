# LLM 审查（glm-5.1）

> 材料来源：material-M15-bindings.md

## 结论
**有条件通过**：核心数据层与解析逻辑设计稳健、安全校验充分，但 diff 严重截断导致调用点归槽无法全面静态验证，且设置分区存在零档案空态未隔离的 UI 缺陷需修复。

## 逐项核对

1. **两档案不同模型时各槽位请求路由**
   - **可判定**：附录 B 提供的 `resolveProfileForSlot` 逻辑完整且正确，优先匹配槽位绑定档案，回落至默认档案或首个档案。
   - **疑点**：材料声称 14 个调用点显式归槽，但提交的 diff 中仅展示了 4 处调用点（`ChapterEditor`、`AssistantDock`、`StyleDigestDialog`、`useMemorySync`）。其余调用点（如 `GenesisView`、`CanvasView`、`usePlotAi` 等）及 `generateWriting` 函数签名的变更均未在 diff 中体现，无法静态全量核对。
2. **未绑定槽位回落默认与删绑定回落**
   - **可判定**：`bindings.ts` DAO 中对 `profileId === ''` 执行了删行操作，`resolveProfileForSlot` 会在找不到绑定行时自然回落至默认档案，逻辑闭环。
3. **删除档案后对应槽位绑定级联清零**
   - **可判定**：Migration v15 建表语句声明了 `REFERENCES api_profiles(id) ON DELETE CASCADE`，附录 B 确认 `database.ts` 存在 `db.pragma('foreign_keys = ON')`，级联清零条件成立。
4. **绑定重启持久**
   - **可判定**：基于 SQLite 持久化表 `agent_bindings`，重启加载逻辑无特殊缓存依赖，必然持久。
5. **设置分区 8 行渲染+即改即存**
   - **可判定（逻辑层面）**：`SlotBindingsSection.vue` 通过 `v-for="slot in AGENT_SLOTS"` 渲染列表，`onPick` 触发 IPC 写入并 `await load()` 刷新，即改即存逻辑正确。
   - **疑点**：零档案时的 UI 交互未隔离（详见“发现的问题”中危项）。
6. **typecheck 零报错+自测零外部消耗**
   - **无法判定**：静态审查无法验证运行时 console 报错与外部消耗；由于 diff 截断，也无法复核是否所有类型变更均已闭合，只能暂信开发方声明。

## 发现的问题

1. **中危：UI 空态未有效隔离**
   - **位置**：`SlotBindingsSection.vue`
   - **描述**：当 `profiles.length === 0` 时，`<div class="flex flex-col gap-1.5">` 依然会渲染 8 个仅含“跟随默认”选项的无意义下拉框，仅仅在下方追加了空态提示文案。应当使用 `v-if="profiles.length > 0"` 包裹 8 行渲染区，或直接将空态提示替换掉列表渲染，避免用户产生无效交互。
2. **低危：ChapterEditor 槽位分流硬编码违背开闭原则**
   - **位置**：`ChapterEditor.vue`
   - **描述**：分流逻辑采用字面量比对 `kind === 'polish' || kind === 'expand' || kind === 'rewrite'`。若后续 `SelectionAction` 联合类型扩展新的划词动作，此处不会触发编译期类型错误，但会导致新动作静默走入 `'writing'` 槽位。建议改用类型守卫 `function isSelectionAction(kind: PanelKind): kind is SelectionAction` 进行收窄。
3. **材料疑点：diff 严重截断**
   - **描述**：核心新增文件 `services/agentSlots.ts` 全文、`generateWriting` 签名修改、以及大部分调用点的参数追加均未出现在 diff 中，仅靠附录 B 补全局部逻辑。导致本次审查无法从主 diff 静态闭环验证 M15 核心要求的“编译期强制显式归槽”。

## 无法判定项

1. **14 个调用点归槽完备性**：由于 diff 截断，无法静态核对除 `ChapterEditor`/`AssistantDock`/`StyleDigestDialog`/`useMemorySync` 外的调用点是否全部正确传入必传的 `slot` 参数。
2. **函数签名真实变更情况**：`useAutoSync` 和 `useMemorySync` diff 中追加了 `, 'extract')` 参数，但未见对应被调函数（如 `generateWriting`）的签名声明变更，无法判定其是否真正接受并处理了该参数。
3. **运行时黑盒行为**：T1-T9 断言的真实性、console 零报错、外部 AI 消耗为 0、以及 SQLite FK CASCADE 在实际运行环境中的确切表现，均属黑盒运行时范畴，静态无法判定。
