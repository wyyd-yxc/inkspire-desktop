## 发现的问题

### 🔴 严重（可能阻塞验收）

- **P0 渲染层 diff 不完整**：所有验收点 4–11 涉及 Vue Flow 节点、详情面板、AI 弹窗、连线编辑器、搜索过滤、拖拽落库——这些代码 100% 缺失。审查员无法核实：
  - 验收点 4 的连线视觉（四色）实现
  - 验收点 5 的卡片样式与词条图标
  - 验收点 6 的标签「顿号分隔」交互
  - 验收点 9 的避让换行算法
  - 验收点 11 的宽容解析/修复器逻辑
  
  → **必须补齐 `src/renderer/src/views/PlotCanvasView.vue` 与 `components/plot/*` 的 diff，或提供完整仓库快照/录屏**。

- **P0 `plot_events.parent_id` 缺 `ON DELETE` 策略注释**：migration 中 `parent_id TEXT` 无 FK 引用，虽备注"恒为 null"，但 schema 上是"无约束的悬空字段"。建议显式 `FOREIGN KEY (parent_id) REFERENCES plot_events(id) ON DELETE SET NULL`（或显式注释留待 M11），避免子画布功能上线时迁移翻车。

### 🟠 中等

- **P1 连线去重方向策略的潜在歧义**（`plotEdges.ts:50-60`）：
  ```sql
  (source_id = ? AND target_id = ?) OR (source_id = ? AND target_id = ?)
  ```
  注释写"反向边视为矛盾"，但在剧情画布语境下"剧情事件 A 影响事件 B" 与 "B 影响 A" 可能是两个独立视角（如闪前/闪回），直接禁反向会剥夺创作语义。建议将"方向去重"改为"同向去重 + 同向 type 合并"，或至少提供 toggle。

- **P1 `updatePlotEvent` 的 tags/wikiRefs 替换语义**：`plot.ts:97-106` 中 tags/wikiRefs 是**整体替换**而非增量；UI 端若只传新增 tag 数组会覆盖既有内容。需确认渲染层 detail panel 的标签编辑是「提交完整数组」还是「增量合并」——后者当前后端会丢数据。

- **P1 `createPlotEvent` 默认落位 `pos_x = (count+1)*340`**：依赖 `COUNT(*)` 行数乘固定步长。新建第二个事件时若上一事件被拖到 x=9999，新事件仍落 x=680，会重叠。AI 落位避让（验收点 9）也复用了同一思路，但缺 `MAX(pos_x)+step` 的算法。建议改为 `MAX(pos_x, default) + step`。

- **P1 UUID 校验 `assertUuid` 漏覆盖 `wiki_refs` 数组内 id**：`plot:create` 仅校验 `bookId`，未对 `input.wikiRefs[]` 校验。渲染层若被污染注入非 UUID 字符串，可能触发下游 wiki 查询异常。建议在 IPC 层 `input.wikiRefs?.forEach(assertUuid)`。

- **P2 IPC 错误未统一 shape**：`wrap` 内部抛错会被序列化为普通 Error，渲染层需依赖 `IpcResult` 的失败分支。建议在 `wrap` 输出 `{ ok: false, error: { code, message } }` 统一契约（核对 sceneEdges 的处理一致性）。

### 🟡 轻微

- **P2 自测报告缺覆盖率**：表格仅列 m10-t1/m10-t2/m10-t2b，未声明脚本内具体断言条数；`m10-t2` 分歧首跑失败未给出失败堆栈摘要，仅说"见下"但下文无具体日志。
- **P2 事件标题默认 `事件 ${count+1}`**：本地化字符串硬编码中英混排，与项目其它中文化不统一；建议改 `i18n` key 或纯中文 `事件 N`。
- **P2 `parseJson` fallback 静默吞错**：tags/wikiRefs 解析失败仅 `console.warn` 返回 `[]`，数据丢失无主流程提示；用户后续保存会覆盖为空，需在 IPC 层显式报 `DATA_CORRUPTED` 错误。
- **P3 自测脚本在 `tmp/`** 而非项目 `tests/` 或 `scripts/`，CI 不可达；后续里程碑回归风险高。
