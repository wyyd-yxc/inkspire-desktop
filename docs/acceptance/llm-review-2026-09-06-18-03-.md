### 验收点 ②：session 赋值时序源码佐证（B2）
**可判定：达成。**

`chatStream` 源码关键时序链路清晰：
1. 先订阅 `onStreamEvent` 并缓冲（`bindRequestId` 空期间全部入队）
2. `await invoke('ai:chat-stream')` 返回 `requestId`
3. 回放 buffer，过滤 `evt.requestId === bindRequestId`
4. **之后才** `return { requestId, abort }` ——此时渲染端 `await` 拿到 session 对象
5. 后续真流事件到达才触发 `dispatch` → `onDone`

故 `generateWriting().then(({ session }) => abort())` 中的 session 必然先于 onDone。可静态判定。

### 验收点 ③：tick 间隔门槛源码（§2）
**可判定：达成，但有 1 处行为疑点。**

```ts
105:    if (!s.enabled) return                       // 早返回
106:    if (Date.now() - lastCheckAt < s.intervalMin * 60_000) return
107:    lastCheckAt = Date.now()
```

材料声称「重新开启后首个 tick 满足间隔立即检测」。但 **`enabled` 是 IPC 异步读，关闭期间 tick 每 ~30s/用户配置跑一次都会异步请求 `loadAutoSyncSettings`** —— 严格说"关闭期间"也算 tick 在转，只是被早返回。**`lastCheckAt` 在关闭期间不更新**，再次启用 + 间隔阈值 ≥ 用户配置 → 首次触发为真。逻辑成立。

`SILENT_MAX_CHAPTERS = 3` 独立保险源码存在，与材料描述一致。

## 发现的问题

### 🔴 中危-1：`mergeWatermarkChapter` 非事务，IPC 边界存在理论丢更新
**位置**：`src/main/db/settings.ts` `mergeWatermarkChapter`
```ts
const row = d.prepare('SELECT value FROM settings WHERE key = ?').get(key)
...
map[chapterId] = wordCount
setSetting(key, map)   // 另一次 prepare+run
```
better-sqlite3 单进程内确实串行安全，但 read 与 write 之间**没有包在 `db.transaction(...)` 中**。虽然 better-sqlite3 同步 API 在 Node 单线程下不会被打断，但这与 r2 回应中强调的「主进程单线程天然原子」论据相比，**用 `db.transaction()` 包裹能更明确表达意图并避免后续重构误改**。建议补一行 `setSetting` 改为：
```ts
const tx = d.transaction(() => { ...read...merge...write... })
tx()
```
**严重级别**：中（功能性无 bug，但与材料论证强度不匹配）。

### 🟡 低危-1：白名单扩展但未收紧
**位置**：`src/main/ipc/settings.ts`
新增 6 个 `sync.*` 键的白名单。`sync.auto_targets` 通常是数组对象，渲染层任意写仍可能写入畸形 JSON；与既有 `ai.default_profile_id` 单值键不在同一风险等级。**建议**：`sync.*` 键统一走 `mergeWatermarkChapter` 或新增 IPC，而非开放通用 `set/get`。

### 🟡 低危-2：`PlotAiDialog` 新增 `contextInfo` 必填属性破坏兼容
**位置**：`src/renderer/src/components/plot/PlotAiDialog.vue`
新增 `contextInfo: string` 为必填 prop。任何旧调用点未传会导致运行期 `undefined` 显示 `✓ undefined`。材料未列出所有 PlotAiDialog 调用点的同步修改。**需静态搜索调用方确认已补 `' '` 或类似空字符串默认**。

### 🟡 低危-3：`App.vue` 启动自动同步但缺停止/单例保护
**位置**：`src/renderer/src/App.vue`
```ts
onMounted(() => startAutoSync())
```
未见 `onBeforeUnmount` 停止、未见 hot reload 防重复 start。若 `startAutoSync` 内部非幂等（未提供源码片段），dev HMR 会导致多定时器并存。**需要运行确认**。

### 🟢 规范-1：ToastHost 移除 `pointer-events-auto`
**位置**：`src/renderer/src/components/ToastHost.vue`
删除了 `pointer-events-auto` 类。若父容器为 `pointer-events-none` 透传场景，toast 将不可点击。属**未解释的样式回退**，疑为误删。

### 🟢 规范-2：`ChapterSidebar` 新 `sync` 按钮无障碍属性缺失
同步按钮仅有 `title`，无 `aria-label`、无键盘焦点环样式（class 中未见 `focus-visible`）。

## 无法判定项

以下条目**必须运行/补充材料才能定论**，本次静态审查不予通过：

1. **`startAutoSync` 的幂等性** —— 未提供 `useAutoSync.ts` 完整源码，无法确认 HMR / 多次 mount 下定时器是否累加。
2. **`plotLoadSeq` 与 `loadPlot` 异常路径** —— `loadPlot` 失败时 `plotCache.value` 保持空对象，下一次成功会被覆盖；但**章节切换时序与 generationSeq 之间的 race** 需运行验证。
3. **`PlotAiDialog` 所有调用点是否已传 `contextInfo`** —— diff 未包含调用方修改。
4. **`mergeWatermarkChapter` 在高频串行调用下的实际行为** —— better-sqlite3 同步 API 理论上原子，但缺乏并发压测数据。
5. **T2/T3/T4 自测原始日志** —— 仅引用「此前会话实录」，无可追溯文件 hash。
6. **`ToastHost` 父级布局是否依赖 `pointer-events-auto`** —— 需 UI 实测。
7. **静默档"关闭开关后立即检测禁用"语义** —— T3 报告称通过，但未明示是哪一档（提醒/静默）下关闭开关的检测时机；`tick()` 早返回在下次 tick（≤ intervalMin）才生效，并非"立即"。需确认"立即"的口径定义。
