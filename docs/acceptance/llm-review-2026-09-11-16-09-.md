## 逐项核对

1. **导入参考 txt→AI 拆解→勾选→风格包生成且来源徽标=拆书（source_type='digest' 落库）**

   - **疑点/无法判定**：验收点要求「列表刷新显示拆书徽标」，但 `StylePackagesSection.vue` 的 diff **仅包含空态文案与入口按钮变更，未见徽标渲染代码**。附录 B 提供了徽标源码摘录，但静态审查无法判定该片段是否真正挂载于列表项模板中（diff 截断）。
2. **该包绑定新书后生成正文风格可感知**
   - **无法判定**：属真实 AI 黑盒感知范围，附录 C 尚为空白。
3. **全不勾确认禁用/取消/拆解失败均不落库；参考文本重启后无任何残留**
   - **可判定部分**：取消与失败逻辑在 `StyleDigestDialog.vue` 中清晰可见（`fail()` 回落导入态、无落库调用）；`watch` 的 `else` 分支显式清空 `pick.value`、`parsed.value`、`candidates.value`，隐私口径有代码实证。全不勾禁用依赖既有 `SyncCandidateDialog`，附录 B 摘录证实 `disabled` 绑定逻辑存在。
4. **超 2 万字截断生效（只取开头）**
   - **可判定部分**：`digest.ts` 中 `DIGEST_TEXT_LIMIT = 20000` 且 `raw.slice(0, DIGEST_TEXT_LIMIT)` 逻辑无误。
   - **疑点**：`digestPrompts.ts`（附录 B）中 `buildDigestMessages` 内部又调用了 `refText.slice(0, REF_TEXT_LIMIT)`。该 `REF_TEXT_LIMIT` 常量未在材料中定义，若其值小于 20000，将导致 UI 显示截取 2 万字，但实际注入 AI 的字数更少，存在口径不一致风险。
5. **删 digest 包走既有解绑链路（FK SET NULL 回落）**
   - **无法判定**：diff 中无删除逻辑变更，材料声称复用既有链路。需运行验证。
6. **typecheck 三重闸门+console 零报错；AI 用例重试≤3**
   - **无法判定**：属运行时与黑盒纪律验证范围。

## 发现的问题

- **中等：核心 UI 徽标渲染缺失 diff 证据**
  `StylePackagesSection.vue` 的 diff 仅仅展示了新增按钮和空态文案更新，未展示验收点 1 核心要求的「拆书」徽标（`p.sourceType === 'digest'`）在 `<article>` 列表中的实际渲染挂载。附录 B 虽有摘录，但作为静态审查员无法确认摘录片段是否真正落入当前版本的模板树中，需补充该文件完整 diff。
- **低：未定义常量 `REF_TEXT_LIMIT` 潜在截断口径冲突**
  `services/digestPrompts.ts` 中使用了 `refText.slice(0, REF_TEXT_LIMIT)`。由于该常量未在附录或 diff 中声明，若其值与 `DIGEST_TEXT_LIMIT`(20000) 不一致，会导致主进程截断给 UI 的字数与渲染层实际发给 AI 的字数不符，造成 UI 欺骗。
- **低：review 阶段退出直接销毁全部上下文**
  `StyleDigestDialog.vue` 在 review 阶段将 `SyncCandidateDialog` 的 `@close` 直接绑定为 `close()`（关闭整个弹窗并清空所有上下文）。若用户在候选面板误触关闭/取消，无法退回 import 阶段保留原文本重试，必须重新选文件。虽符合「隐私不持久化」承诺，但 UX 体验略显粗暴。
- **信息：JSON 解析大括号截取法的极端容错隐患**
  `parseDigestOutput` 采用 `indexOf('{')` 至 `lastIndexOf('}')` 截取。若 AI 输出包含 `{ "a": 1 } 无关文本 { "b": 2 }`，该截取将生成非法 JSON 字符串。虽有 `lenientParse` 兜底，但材料未展示 `lenientParse` 对此类畸形结构的处理能力，存在解析失败风险（T2-c 仅验证了 markdown 围栏与前后杂文本，未覆盖多对象夹杂场景）。

## 无法判定项

1. **「拆书」徽标在设置列表中的真实渲染**（依赖被截断的 `StylePackagesSection.vue` 源码）。
2. **`SyncCandidateDialog` 全不勾禁用与缺省 `tagColor` 渲染健壮性**（属 M10.5 既有组件，本轮 diff 无该组件源码，仅依附录 B 摘录相信）。
3. **`REF_TEXT_LIMIT` 的实际值与截断一致性**（材料未提供定义）。
4. **验收点 2（AI 风格注入感知）、验收点 5（FK SET NULL 回落）、验收点 6（typecheck/console 零报错）**（需真实运行环境与黑盒验证）。
5. **`digest:pick-text` 通道真实断点调试与字节级残留验证**（材料声称主库+WAL 字节搜索为 0，静态审查无法复验）。
