## 发现的问题（含严重级别）

### 1. [严重] 关键业务逻辑代码缺失（审查盲区）
- **位置**：Diff 截断处（`useReverseSync.ts`, `plotPrompts.ts`, `useWikiCleanup.ts`, `wikiPrompts.ts` 等）。
- **描述**：M10.7 的核心卖点“正文反向受限更新”与 M10.6 的“实体名提取”算法代码均不在提供的 diff 片段中。仅凭 `SyncCandidateDialog.vue` 的 UI 变更无法确认底层逻辑是否安全（如 DOM 操作是否安全、引用转移是否彻底）。
- **建议**：需补充关键文件全量代码或完整 diff 进行二次审查。

### 2. [一般] `findDuplicate` 全表扫描性能隐患
- **位置**：`src/main/db/wiki.ts` -> `findDuplicate`。
- **描述**：`SELECT id, name, type FROM wiki_entries WHERE book_id = ?` 在每次创建/更新词条时均拉取该书全量词条至内存进行遍历比对。
- **分析**：虽然当前数据量下性能可接受，但不符合最佳实践。
- **建议**：后期优化建议利用 SQL 查询缩小范围（如 `WHERE name = ? OR name LIKE ?`），或利用内存索引。

### 3. [建议] `normNameDup` 标点过滤遗漏
- **位置**：`src/main/db/wiki.ts` -> `normNameDup`。
- **描述**：正则过滤了常见中英文标点，但未包含书名号《》等特殊符号。若用户输入「林昭」与「《林昭》」，经 norm 后分别为「林昭」与「林昭」，判定为重；若输入「林昭」与「林昭。」亦判定为重。这符合“严查重”口径，但需确认是否符合业务预期（提示词中是否有相应引导）。
- **判定**：按材料所述“统一判定”口径，判定为通过，但建议补充测试用例覆盖带书名号场景。

## 无法判定项（需补充代码或运行验证）

1.  **正文反向替换的安全性**：需验证 `DOMParser` 实现是否严格限定在文本节点，是否正确处理了跨行选中、标签属性值误改等边界情况。
2.  **实体名提取准确性**：`extractEntityName` 是否能正确处理“无分隔符长文本”、“特殊符号分隔”等边界情况，需查看源码。
3.  **引用转移逻辑**：M10.6 整理词条中的“引用转移”涉及修改剧情/场景的外键引用，需验证其事务完整性（是否全部成功或全部回滚）。
4.  **剧情提取去重逻辑**：`buildPlotExtractMessages` 注入已有事件链的具体实现，需防止 AI 对已有事件的重复生成。
