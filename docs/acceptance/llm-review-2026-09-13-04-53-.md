## 发现的问题

### P1 · 高：离开写作台路由时 flushSave 被守卫拦截，待存草稿可能丢失

**位置**：`WorkspaceView.vue`（附录 B 切章保存段）

```ts
watch(() => route.query.ch, () => {
  if (route.name !== 'workspace') return  // ← 缺陷守卫
  void flushSave()
})
```

**问题**：当用户从写作台导航到同壳下其他功能页（如点击左栏"设定集"），路由从 `/book/:id/write?ch=abc` 变为 `/book/:id/wiki`。此时：
1. `route.query.ch` 从 `"abc"` 变为 `undefined`，watch 触发
2. `route.name` 已变为 `'wiki'`，守卫直接 return
3. `flushSave()` 未被调用
4. 若用户在 1.5s 防抖窗口内点击导航，pendingContent 中的草稿不会落盘
5. WorkspaceView 卸载后，防抖定时器虽可能仍触发但处于已卸载组件上下文，行为不可靠

**影响**：写作应用中丢失最近 1.5 秒输入是**数据丢失级缺陷**。自测 T3 仅测试章间切换（route.name 不变），未覆盖此场景。

**修复建议**：移除 route.name 守卫，或增加 `onBeforeUnmount(() => flushSave())` 兜底。

---

### P2 · 中：flushSave 先清 pendingContent 再异步落盘，异常时内容不可恢复

**位置**：`WorkspaceView.vue` — `flushSave()`

```ts
async function flushSave(): Promise<void> {
  const pending = pendingContent.value
  if (!pending) return
  // ...
  pendingContent.value = null  // ← 同步清空
  /* chapters.update(target.id, ...) + 共享数组原位更新 */ // ← 异步操作在后面
}
```

**问题**：`pendingContent.value = null` 在 await 之前同步执行。若后续 `chapters.update()` 抛异常（磁盘写入失败等），pending 引用已丢失，草稿无法重试或恢复。

**修复建议**：将 `pendingContent.value = null` 移至异步操作成功之后，或在 catch 中恢复。

---

### P3 · 中：AiWritingPanel flushTimer 无卸载清理

**位置**：`AiWritingPanel.vue`

```ts
let flushTimer: ReturnType<typeof setTimeout> | null = null
// ...append() 中设置 flushTimer
// 无 onBeforeUnmount 清理
```

**问题**：组件卸载时若 flushTimer 仍在等待，回调将在已卸载组件上下文中执行 `text.value += buf`。虽实践上通常无害（ref 仍被闭包持有至 GC），但属于资源泄漏与潜在运行时异常。

**修复建议**：添加 `onBeforeUnmount(() => { if (flushTimer) { clearTimeout(flushTimer); flushBuf() } })`。

---

### P4 · 低：stopGeneration() 中 seal() + finish() 冗余调用

**位置**：`ChapterEditor.vue`

```ts
function stopGeneration(): void {
  activeSession?.abort()
  activeSession = null
  isBusy = false
  panel.value?.seal()   // flushBuf + sealed=true
  panel.value?.finish() // flushBuf(no-op) + sealed=true(重复) + phase='ready'
}
```

**问题**：`finish()` 已包含 flushBuf + sealed=true，前置 `seal()` 完全冗余。不影响正确性，但增加理解成本，暗示 seal/finish 职责边界不清。

**建议**：只保留 `panel.value?.finish()`，或在 stopGeneration 场景使用专用的 `sealAndFinish()`。

---

### P5 · 低：BookCard 删除键双重透明度叠加可能触屏难辨

**位置**：`BookCard.vue`

```html
class="... text-white/60 opacity-70 ..."
```

**问题**：`text-white/60`（color alpha 0.6）× `opacity-70`（整体 alpha 0.7）= 有效文字透明度 ≈ 0.42。在深色卡片背景上可能极难辨识，且触屏设备无 hover 态，始终以此透明度呈现。与 L39「触屏键盘可达」的初衷存在张力。

**建议**：移除 `text-white/60` 改为 `text-white`，仅靠 `opacity-70` 控制弱显；或触屏媒体查询提高基础可见度。

---

### P6 · 低：ToastHost 离场 `display:none` 依赖 Vue Transition 对 0s duration 的隐式检测

**位置**：`ToastHost.vue`

```css
.toast-leave-active {
  display: none;
}
```

**问题**：Vue Transition 组件通过 `getComputedStyle` 检测 transitionDuration 为 0s 时立即完成离场。此行为虽符合 Vue 3 源码逻辑，但属框架隐式行为，若 Vue 版本升级或浏览器对 `display:none` 元素的 computed style 返回值变化，可能回归 DOM 残留。更稳健做法是同时设置 `:duration="0"` 显式声明。
