# LLM 审查（MiniMaxAI/MiniMax-M3）

> 材料来源：material-M16-package.md

## 结论

**有条件通过** — 交付物齐全、烟测脚本可复核、关键工程风险（better-sqlite3 ABI、userData 共享）有自洽论证；但 git diff 失败、图标多尺寸缺失、未签名 SmartScreen 风险未在产品层提供缓解，作为首版打包可接受，建议补做后两项再标里程碑正式完成。

## 发现的问题

### 🔴 严重

**P1. diff 收集失败，代码变更完全不可审查**
材料末尾明文 `fatal: bad revision 'v0.5.0..HEAD'`——这意味着审查员**根本无法核对 src/、electron-builder.yml、package.json 的真实改动**。E 节虽补交了 electron-builder.yml 与 package.json 关键字段，但：
- 是"补交全文"还是"截取片段"？未声明
- `dependencies` 字段被 `…` 截断（TipTap 三件套之外是否引入 electron-updater？是否有可疑新增依赖？）
- src/ 内的 preload、main 进程、IPC 任何改动均完全黑箱

**这违反了验收材料最基本的形式要求。**审查员无法判断本次里程碑是否引入了回归/安全风险。建议：在合并前必须重跑 diff 并贴出，或至少提供 commit hash 让审查员可定向拉取。

### 🟡 中等

**P2. userData 共享机制仅靠推论，无运行时实证**
"开发版与安装版共享 %APPDATA%/inkspire-desktop"在 Electron 文档层面成立，但材料未展示：
- 烟测执行前后该目录的文件清单（ls -la）
- 默认档案 `GMI Cloud · MiniMax M3` 的实际落盘位置（应在 userData 而非 app.asar 内）

如果该档案实际是**打包在 app.asar 内随应用分发**而非写入 userData，则"全新机器需手动配置"的说法就需要修订，反之亦然。

**P3. NSIS 静默安装与卸载仅口头声明**
验收点 6 声称"安装后应用可启动、可写作；卸载入口存在"，但缺少：
- `/S` 安装的 stdout/stderr
- 安装后目录结构（`C:\Users\xxx\AppData\Local\Programs\墨灵\` 或用户选定目录）
- 卸载条目在控制面板的截图

**P4. 图标硬证据缺失**
仅有 `tmp/icon-preview.png`（自渲染的预览图），不等于实际生效。需补：
- `InkSpire.exe` 右键属性 → 图标页签截图
- 桌面快捷方式图标截图
- 任务栏窗口图标截图
- 多尺寸 ICO 内嵌情况（已知边界，仅 256×256）

### 🟢 轻微

**P5. smoke 脚本存在超时但未断言清理**
F 节 `setTimeout(..., 120000)` 后强制 `finish()` 但不取消 setTimeout，AI 流式超时场景下 Node 进程不退出（依赖 `ws.close()` 不够，需 `process.exit(0)`）。属于脚本健壮性问题，不影响本次验收结论。

**P6. 烟测发现 page 失败时打印了完整 url/cookie 等敏感字段**
`throw new Error('未找到应用页面: ' + JSON.stringify(targets?.map((t) => t.url)))`——若生产环境误用此脚本调试，可能泄露本地调试端口的页面 URL 与 wsDebuggerUrl 到日志。仅脚本内部风险，标轻。

**P7. asarUnpack 配置语义可疑**
`asarUnpack: ["resources/**"]` 通常仅需列具体原生模块路径（如 `**/better-sqlite3/**`），整段 `resources/**` 排除会让 asar 打包几乎退化为明文目录，体积与冷启动均受影响。需确认是否有其他资源确实需要 unpack，否则应收窄到最小集。

**P8. ELECTRON_MIRROR / ELECTRON_BUILDER_BINARIES_MIRROR 设置未声明作用域**
开发自测声明使用国内镜像，但材料未说明：
- 是否写入 `.npmrc` / `.electron-builder.env`
- 是否会被提交到仓库（若是，新机器 clone 后开发者也会被迫走镜像，构建可重现性下降）

## 无法判定项

以下事项静态审查无法确认，需运行时或环境实测：

1. **实际安装行为**：NSIS 安装包在全新 Windows（无 Visual C++ Runtime、无 WebView2 等）的兼容性 —— 材料声明已验证但未贴日志
2. **SmartScreen 拦截等级**：未签名的具体拦截表现因 Windows 版本与时间而异
3. **DPI 缩放下 256×256 单尺寸 ICO 的视觉质量**：仅"Windows 自动缩放"声明，肉眼效果未截图
4. **数据库文件在重装/升级后是否被识别**：0.6.0 为首个安装包，未来升级场景（M17+）的兼容路径未验证
5. **macOS / Linux 平台打包**（如属于本里程碑范围）：材料完全未涉及，仅 Windows
6. **AI 默认档案在 production 环境的 baseURL/Key 配置来源**：用户提到 `GMI Cloud · MiniMax M3`，但**用户是否需自带 API Key、是否应用内置了 gateway**——决定"全新机器开箱即用"承诺的真实性。材料仅说"默认档案在设置中心可见"，未说明是否已内置可用的 baseURL

### 审查建议

**优先补 P1（diff 可复现性）与 P3（NSIS 安装/卸载实证）后再标通过**；P2/P4 在 M17 首个迭代解决即可；P5–P8 纳入后续代码审查 checklist。
