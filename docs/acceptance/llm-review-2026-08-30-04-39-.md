## 发现的问题

### 🔴 严重

1. **asarsar 配置存在结构性疑问（`asarUnpack` 与 `files` 范围不一致）**
   - 配置 `files` 包含 `out/**` 但 `asarUnpack` 仅声明 `resources/**`。`better-sqlite3` 的 native 二件实际位于 `node_modules/better-sqlite3/...`——它会被默认打入 `app.asar` 中（如未显式 unpack）。B 节称存在于 `app.asar.unpacked/node_modules/better-sqlite3/prebuilds/...`，但 `asarUnpack` 列表中并无 `node_modules` 或 `**/better-sqlite3/**` 的 unpack 规则。**电子打包器默认会自动 unpack 含 `.node` 的包**，但这是隐式行为；显式规则缺失使结果依赖于 builder 默认策略，建议显式添加 `asarUnpack: ["**/*.node"]` 或 `**/node_modules/better-sqlite3/**` 以固化行为。

2. **配置文件被显式打包（潜在源码泄露）**
   - `files` 黑名单不含 `tsconfig.node.json` / `tsconfig.web.json` / `.gitignore`，仅排除了 `.vscode`、`src/*`、`electron.vite.config.*`。`tsconfig.*` 仅影响构建，不会被 `out/**` 收录，无问题；但**未排除 `node_modules/.bin/**` 中的可执行脚本、`.npmrc`、`pnpm-lock.yaml`**——黑名单已含这些。可保留。

### 🟡 中等

3. **`files` 未限制 `package.json` / `LICENSE` 等元数据排除**
   - `out/**` 打包范围下根 `package.json` 会被打包（其本身是合理的，main 入口需要）；无大问题。但若仓库中含 `.github/`、`.husky/` 等开发脚本，**默认会被 electron-builder 通过 `extraResources` 之外的 `files` 规则误打进 app.asar**。材料中只展示了部分 `files`，未排除 `.github/**`、`.husky/**`、`*.log`。

4. **`productName: 墨灵` 与安装路径命名不一致**
   - NSIS 默认安装到 `%LOCALAPPDATA%/Programs/InkSpire/`（英文名），但 `productName` 是中文「墨灵」，快捷方式名也是「墨灵」。安装路径用拼音导致用户难以在资源管理器中识别，且与品牌不一致。建议显式设置 `nsis.installDirectoryName` 或在 README 中说明。

5. **`executableName: InkSpire` 未配合 `artifactName` 中的 `墨灵` 元素**
   - exe 名 InkSpire（英文），但 NSIS UI 显示「墨灵」——安装后桌面快捷方式指向 InkSpire.exe，普通用户可能困惑。

### 🟢 轻微 / 规范

6. **`description` 中出现「复刻自 inkspires.cn」字样**
   - 写在打包后 package.json（`out/...` 不影响，但根 package.json 同样被 pack），存在品牌/法律措辞风险。建议在交付前改为中性描述。

7. **未做代码签名（已知边界）**
   - 开发方已声明。属于「不阻断」但建议至少给出临时 `signtool` 配置占位与 README 中的「如何签名」说明。

8. **`postinstall: electron-builder install-app-deps` 与 `npmRebuild: false` 冲突**
   - `install-app-deps` 会强制 rebuild 原生模块。开发方在 `npmRebuild: false` 注释中说明机器无 Python/VS 环境，但 `postinstall` 会在 `npm install` 时触发——若 CI 或新机器执行 `npm install`，`install-app-deps` 会失败。**建议明确文档化 `npm install --ignore-scripts`**，否则下次构建复现性会出问题。

9. **版本号 `typescript: ^7.0.2` 存疑**
   - TypeScript 截至当前未发布 7.x 主版本（最新稳定为 5.x）。可能是 dev 拼写错误或私有 registry 镜像版本——需确认。

10. **`@tiptap/*` 三件套均为 `^3.30.2`**
    - 同步锁版本 OK；Tiptap 3.x 为较新主线，与 Vue 3 兼容性需运行时确认。属「无法判定」项。

## 无法判定项（需运行验证）

下列条目材料仅给出开发方自报输出，本审查无法独立复现，建议第三方或 CI 实测：

1. **better-sqlite3 NAPI 与 Electron 43 的 ABI 兼容**——仅靠「烟测 books.list ok」自证，独立运行时验证未提供
2. **J 节 NSIS 静默安装黑盒验收全部断言**（退出码、注册表、卸载入口、CDP 验证、AI 流式回复「安装成功」）
3. **升级迁移路径**——0.6.0 为首个安装包无旧版迁移，但 0.7.0 升级至 0.7.x 时 installer 的 `upgrade` 行为是否覆盖 `%APPDATA%` 数据未覆盖
4. **卸载后是否残留 `%APPDATA%/inkspire-desktop`**（按 NSIS 默认行为，userData 目录不会被删除——属正常行为，但应在交付文档中说明）
5. **应用首次冷启动时间、内存占用、Spark 渲染器进程数**（性能维度未提交）
6. **Windows Defender / SmartScreen 在干净环境的实际拦截体验**（开发方声明需用户点「仍要运行」，但未给出录制或截图）
7. **多 DPI 显示器下图标视觉一致性**（仅 256×256）
8. **asar 完整性 / electron 43 的 asar 校验**（某些 Electron 版本对 asar 内文件有签名校验，未在材料中确认）
9. **AI 真实流式响应在打包产物中的重试/超时行为**（脚本设了 120s 超时，但实际响应延迟与稳定性需多轮抽样）
10. **应用挂起/崩溃时 native 模块的清理**（better-sqlite3 句柄释放与 .node 卸载是否干净）
