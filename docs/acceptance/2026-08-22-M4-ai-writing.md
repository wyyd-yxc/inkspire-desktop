## 发现的问题

| # | 级别 | 问题 | 位置/根因 |
|---|---|---|---|
| P1 | **阻断** | 流式期间并发锁失效：busy 在会话建立后即释放，生成中再点「✦ AI 续写」不被拦且真实发出并行第二个请求（铁证：两个 requestId 均完整 done），双倍 token 计费、两流文本交错拼进同一面板；且 activeSession 被后发请求覆盖，先发流无法通过「停止」中止。验收点 5「重复点击被拦」不满足 | `ChapterEditor.vue` `runGeneration` 的 `finally { if (mySeq === generationSeq) busy = false }` —— 应改为在 onDone/onError（含 abort 后）才释放 busy |
| P2 | 一般（高） | 面板跨生成不重置：停止/完成后不关面板再发起（再点续写或点「↻ 重写」）时，AiWritingPanel 仅在 `visible` 翻转时重置，面板未关 → 旧文本残留拼接、phase 停留 ready →「■ 停止」按钮缺失（该次生成无法中断）、「✓ 采纳插入」流式中途即可点击（可采纳半截文本）。实测：重写后 3s 面板仍 1212 字残留、无停止钮、采纳钮在 | `AiWritingPanel.vue`（watch 仅监听 visible）与 `ChapterEditor.vue` `runGeneration`（发起时未重置面板）—— 发起时应显式 reset（text=''/phase='generating'） |
| P3 | 轻微 | 用户主动点「停止」后弹出 error toast「已中止」（abort 事件走 onError 链），违背规范 §7「中断不算错误」的精神；仅展示层噪音 | `openaiCompatible.ts` abort→error 事件 + `ChapterEditor.vue` onError 无差别 toast |
| P4 | 轻微 | 划词采纳被拒后再点「采纳插入」：selectionTarget 已置 null，三分支都不命中 → 直接关面板并 toast「已插入正文，记得保存」，实际未插入任何内容（误导） | `ChapterEditor.vue` `acceptGeneration` 拒绝分支置 null 后未禁用采纳按钮 |
| P5 | 轻微 | 采纳文本段落塌陷：面板多段文本（含 \n\n）经 insertContent/setContent 采纳后，换行以字面 \n 存进单个 `<p>`，HTML 渲染时 \n\n 塌陷为空格 → 视觉上合并为一段（续写/划词/整章润色均如此；网文分段排版受损；wordCount 与数据无损） | `ChapterEditor.vue` 采纳分支未将纯文本按 \n\n 拆分为段落节点 |
| P6 | 轻微 | 命名规范：`busy` 布尔未用 is/has/can 前缀（规范 §3）；另 `panelVisible` 同类（Vue 习惯用法，从宽） | `ChapterEditor.vue` |
| P7 | 信息（流程） | 库中存有历史残留测试书 14 本中的 6 本（SELFTEST-M4b×3 等），说明既往会话/自测脚本清理不彻底；本次已全部清除（终态 0 书）。另：验收开始时存在残留 Electron 实例占用 9222（材料自身警告的 HMR 状态污染风险源） | 测试纪律 |
