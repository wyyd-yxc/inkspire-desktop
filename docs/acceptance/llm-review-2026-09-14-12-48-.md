# LLM 审查（glm-5.1）

> 材料来源：material-M17-visual.md

## 结论
**有条件通过** —— 核心 FOUC 灭除链路及深色适配架构经多轮整改已闭合，但关键源码 diff 严重截断，且启动画面退场依赖硬编码延时存在视觉隐患，部分默认值逻辑存疑。

## 逐项核对

1. **双主题切换生效且持久**：材料声称三模式，diff 中可见主进程 DB 读取→`additionalArguments`→preload 注入→内联脚本同步挂载 `data-theme` 的完整灭 FOUC 链路，逻辑严密。但 `useTheme.ts` 及 `AppearanceSection.vue` 的 diff 缺失，无法静态验证 reactive 监听与设置面板交互。
2. **深色主题下关键元素可读**：diff 可见 `text-white` 全面替换为 `text-on-primary`，遮罩换用 `bg-scrim`，输入框换用 `border-ink-border-strong`。splash 区域对比度经 r2 整改已有显式深色覆盖规则。但全量 19 项对比度验算依赖外部脚本与 `theme.css`（diff 缺失），仅能信任自测声明。
3. **封面九题材渲染**：diff 完全截断，`coverArt.ts` 与 `BookCover.vue` 未见，仅能依赖附录 B 的文字摘要与自测截图声明，静态无法核实 SVG 底纹与排版策略。
4. **字体本地加载成功**：diff 新增了两个 woff2 二进制文件，splash CSS 中可见 `font-family: 'Noto Serif SC'`，但 `@font-face` 声明未见（应在缺失的 `theme.css` 中），CSP `default-src 'self'` 允许本地加载，逻辑自洽。
5. **品牌资产**：`brand.ts` 导出函数与 `index.html` 的 splash SVG 结构匹配，图标尺寸链在 `electron-builder.yml` 中有配置。splash 移除逻辑在附录 B 的 `main.ts` 中，diff 缺失。
6. **焦点环/滚动条/输入框边框令牌生效**：组件 diff 可见输入框统一为 `border-ink-border-strong`，全局 `:focus-visible` 规则声明在缺失的 `theme.css` 中。
7. **typecheck + 0 报错**：纯运行时声明，静态无法判定。

## 发现的问题

- **中：启动画面退场时机硬编码（隐患）**  
  附录 B 中 `main.ts` 使用 `setTimeout(60ms)` 触发 splash 淡出。若 Vue 挂载及首帧渲染耗时超过 60ms（在低配机器或冷启动时极常见），splash 会提前消退，暴露未渲染完毕的白屏/骨架屏，造成比 FOUC 更严重的视觉闪烁。应改用 Vue 的 `onMounted` 钩子或特定组件的就绪信号来驱动退场。

- **中：主进程 DB 读取的默认值与业务可能不符**  
  `createWindow` 中 `getSetting('ui.theme', 'light')` 在 DB 未就绪或无记录时回落为 `'light'`。若应用首次安装的默认主题遵循系统（即 system），且用户系统为深色，主进程注入 `light` 会导致首帧闪白，随后被渲染层 `useTheme` 修正为深色，形成二次 FOUC。回落值应与产品初始默认主题保持一致（如 `'system'` 或让内联脚本在 `injected` 为空时强行走 `matchMedia` 分支，当前内联脚本已处理了非 dark/light 的情况，但主进程传来的 `'light'` 会被当做用户显式设置而绕过 `matchMedia`）。

- **低：`<head>` 中 `html` 背景色缺乏 `data-theme` 覆盖规则**  
  `index.html` 的 `<style>` 中仅用 `@media (prefers-color-scheme: dark)` 控制 `html` 背景，但未像 `#boot-splash` 那样提供 `html[data-theme='light'] { background: #faf8f3 }` 覆盖。当用户设浅色+系统深色时，内联脚本虽正确挂载了 `data-theme="light"`，但 `html` 背景仍被 media query 锁死在深色，直到 Vue 挂载后 `theme.css` 生效才修正。当前因 splash 遮挡未暴露给用户，但属于 CSS 逻辑残缺。

- **低：输入框焦点样式冲突风险**  
  diff 中输入框带有 `outline-none focus:border-ink-primary`，而全局声明了 `:focus-visible` 焦点环（双 box-shadow）。同时改变边框颜色与显现焦点环，在视觉上可能导致边框色与焦点环色叠加显得脏乱，且 `focus:border` 不区分键盘/鼠标聚焦，破坏了 `:focus-visible` 的无障碍初衷。

## 无法判定项

1. **`useTheme.ts` 响应式逻辑**：是否正确监听 `matchMedia` 变化并实时切换，及 `initTheme()` 是否存在异步初始化时差。
2. **`theme.css` 令牌定义完整性**：semantic 层双主题色值是否全覆盖，`:focus-visible` 与滚动条规则优先级是否正确。
3. **封面系统实际渲染**：九题材 SVG 底纹是否均存在且无语法错误，排版策略在极端书名长度下的鲁棒性。
4. **`@font-face` 声明**：woff2 文件是否被正确引用且 `font-weight` 匹配。
5. **运行时表现**：splash 移除的 60ms 延时在真实低配设备上是否过早，深色模式下的对比度是否确实达标。
