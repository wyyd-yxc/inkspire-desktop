## 发现的问题

### 轻微-1（观察，非阻断）定魂 AI 辅助的主角名与用户设定不一致

**现象**：用户在 step2 手动填的 logline 主角名「阿璃」，AI 辅助起草时另起炉灶生成主角名「林星野」（基于书名「星镜录」+简介推演）。这是 AI 创作自由度的预期表现，非 bug——AI 辅助本就是「起草建议」，采纳后用户可手动改。但若用户期望 AI 沿用已填人名，需手动调整。

**影响**：无功能影响。仅提示用户：AI 辅助是「起草」而非「续写已有设定」，采纳后请人工校对主角名等关键设定一致性。

**建议**：可在 `buildSoulAssistMessages` 的 user prompt 中追加一句「若已有人名/设定线索请沿用」（当前 prompt 仅给书名/分类/简介）。属体验优化，不阻断本里程碑。

## 遗留与建议

1. **轻微-1** 已记录，建议下个里程碑在定魂辅助 prompt 中引导 AI 沿用已有线索，可挂 roadmap 技术债。
2. 本次验收期间观察到 TokenRhythm API 偶有「流式 done 但零 chunk」的空响应（直接 chatStream 复核时一次返回 0 字、一次 687 字，UI 续写一次 12s 返回完整内容）——这是上游 API 间歇性，非应用代码问题；应用侧空响应表现为面板停在「等待模型输出…」无采纳按钮（符合 `finish()` 仅在 `text.trim()` 时转 ready 的设计），用户重试即可。建议后续可在 `onDone` 时若 zero-chunk 给出「模型未返回内容，请重试」的友好提示（体验优化，非阻断）。
3. 自建自清已执行：删除测试书「星镜录」，结束态 0 书 / 1 档案（基元律动 intact）/ taskkill electron（0 进程残留）；验收用 CDP 临时脚本已清除。
