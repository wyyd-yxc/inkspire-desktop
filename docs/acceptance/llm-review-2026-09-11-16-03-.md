## 发现的问题

### #1 [中等] `startDigest` 竞态缺陷：chatStream 返回后未校验代次号，停止操作可能无法中断网络请求

**位置**：`StyleDigestDialog.vue` `startDigest()` 第 79-99 行

**问题**：
```
phase.value = 'running'
const profile = await resolveProfile()   // ← 此处用户可能点击"停止"
session = await chatStream(profile, ...)  // ← 返回后未检查 mySeq !== seq
```

用户在 `resolveProfile()` 执行期间点击"停止"时：
1. `stop()` 执行 `seq++` + `session?.abort()`（此时 session 为 null，无操作）+ `session = null`
2. `resolveProfile()` 返回后，`session = await chatStream(...)` **将新创建的流赋给 session**
3. 新流的 `onChunk`/`onDone`/`onError` 回调虽因 `mySeq !== seq` 被忽略，**但底层网络请求未被 abort**
4. AI 额度被静默消耗——与材料声称的"停止→真中断网络"矛盾

更恶劣的衍生场景：停止后用户立即重选文件触发第二次 `startDigest`，第一次的 `session` 引用被覆盖，**第一次的流彻底无法 abort**。

**修复建议**：
```typescript
session = await chatStream(profile, buildDigestMessages(pick.value.text), { ... })
if (mySeq !== seq) {       // ← 补充代次号校验
  session.abort()
  session = null
  return
}
```

**同源问题**：`catch` 块（第 97-99 行）同样未检查 `mySeq !== seq`，`resolveProfile()` 抛错时会调用 `fail()` 覆盖 `stop()` 已设置的"已停止拆解"消息。

---

### #2 [低] 关闭弹窗时未清空 AI 拆解结果（`parsed` / `candidates`）

**位置**：`StyleDigestDialog.vue` `watch` 的 `else` 分支

**问题**：
```typescript
} else {
  // 隐私：关闭即丢弃参考文本
  pick.value = null
  // ← 缺少 parsed.value = null 和 candidates.value = null
}
```

材料隐私承诺为"关闭即丢弃参考文本"，代码仅清空 `pick.value`（用户原文）。`parsed.value`（AI 拆解出的调性/规则/样例）和 `candidates.value` 在弹窗关闭后仍驻留内存，直到组件卸载或下次打开时重置。

虽不违反"不落库不落盘"的硬承诺，但 AI 拆解产物是参考文本的派生数据，从隐私口径一致性角度应同步清空。

---

### #3 [低 / 信息] `buildCandidates` 中规则项缺少 `tagColor` 属性

**位置**：`StyleDigestDialog.vue` `buildCandidates()`

```typescript
d.rules.forEach((r, i) => items.push({ key: `rule:${i}`, title: r, tag: '规则', checked: true }))
// ← tone 和 sample 都有 tagColor，rule 没有
```

如果 `SyncCandidateItem` 类型要求 `tagColor` 必填，将触发 typecheck 错误；如果可选，则为视觉不一致（规则项标签无颜色）。**无法判定**——需查看 `SyncCandidateItem` 类型定义。

### #4 [信息] `digestPrompts.ts` 关键实现被 diff 截断，无法静态验证

diff 在 `digestPrompts.ts` 第 85 行处截断，以下关键声明**无法验证**：
- system 提示词是否确实包含"不要分析情节、人物、世界观"约定

- `sanitizeDigest` 是否实现 name ≤30 / tone ≤100 / rules ≤20×100 / sample ≤200 的白名单清洗

这些是验收点 1 和材料附录 A 中 r1 裁定的核心依据，**缺此无法完成完整审查**。
