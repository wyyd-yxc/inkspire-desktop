# LLM 审查（glm-5）

> 材料来源：material-M10.8-r3.md

## 结论
**有条件通过** —— 核心整改（统一事务与白名单守卫）在静态层面逻辑严密且已生效，但材料对 UI 同步与全局残留的证据链因 diff 截断存在断层，需补充关键源码方可闭环。

## 逐项核对

| 二轮条目 | 验收判定 | 材料疑点与静态审查意见 |
|---|---|---|
| **中-1** 映射语义 | **可接受（登记维持）** | 材料称「非不可逆数据损伤」，但审查 v11 迁移 SQL `UPDATE books SET genre = '现实主义' WHERE genre IN ('都市', '言情');` 实际上**抹除了原有「都市/言情」的细分类目信息**。虽然字段为字符串可由用户手动修改，但数据库层面无法区分哪些书原为「都市」、哪些为「言情」，映射是静默且不可逆的。作为已登记的计划内变更，可接受，但材料措辞「非不可逆」有粉饰嫌疑。 |
| **中-2** UI 题材选项同步 | **无法判定（材料不足）** | 材料引用了 `BookCreateDialog.vue L83` 等行号，但提供的 diff 中**并不包含** `BookCreateDialog.vue`、`BookCard.vue` 以及 `BOOK_GENRES` 常量的定义变更。由于无法静态确认常量已被更新且无旧值硬编码，此条存疑。 |
| **中-3** diff 截断固有 | **无法判定（材料不足）** | 材料称「附录 A 已含相关执行器」，且 diff 末尾确实以 `…(diff 已截断)` 中断。作为外部静态审查员，无法查阅被截断的代码与附录 A，因此无法证实「全局零残留」的 grep + CDP 走查结果是否属实。 |
| **低-4** SQL 表名拼接 | **已达成** | 代码变更实证清晰：`database.ts` v11 迁移中引入 `const ALLOWED_TABLES = new Set(['plot_events', 'scenes'])`，且在 `retag` 闭包起始处执行 `if (!ALLOWED_TABLES.has(table)) return`。表名拼接 `${table}` 在白名单守卫下安全，彻底阻断了未来调用方注入非法表名的风险。 |

## 发现的问题

*   **[中] 统一事务重构存在变量收窄的隐患（`database.ts`）**
    *   **描述**：为解决 TS 类型非空推断，代码引入 `const d = db as Database.Database` 并在 `d.transaction` 中执行迁移。虽然静态可判定，但 `m.migrate?.(d)` 将 `d` 传递给 v11 的 JS 迁移函数，而在 `migrate` 函数内部，又再次调用了 `db.transaction((table: string) => {...})` 创建嵌套事务（better-sqlite3 表现为 SAVEPOINT）。
    *   **隐患**：嵌套事务在异常抛出时的回滚行为极其依赖底层驱动实现。如果 JS 迁移内部某行抛出异常，SAVEPOINT 回滚后，外层统一事务是否能正确感知并回滚 SQL 语句与版本记录插入，需运行验证；静态审查无法 100% 担保嵌套事务的失败隔离符合开发者预期。
*   **[低] 迁移 JS 逻辑中的 prepare 语句位置不佳（`database.ts`）**
    *   **描述**：在 v11 的 `migrate` 函数中，`const update = db.prepare(...)` 被放置在 `db.transaction` 回调闭包内部。
    *   **规范违背**：尽管 better-sqlite3 内部有预编译缓存，但在循环或事务闭包内执行 `prepare` 违背了 SQL 预编译语句应尽可能复用的最佳实践。应将 `prepare` 提升至 `retag` 函数外层或循环外。
*   **[低] 静默数据篡改缺少用户感知机制**
    *   **描述**：v11 迁移直接修改了 `genre` 和 `tags`。材料虽声称「保留用户自主修正能力」，但并未提供任何 UI 提示或迁移日志告知用户「你的数据已因版本更新被重新映射」。这在严肃写作软件中可能导致用户对数据一致性的困惑。

## 无法判定项

1.  **UI 题材选项是否真正同步（中-2）**：缺失 `BookCreateDialog.vue`、`BookCard.vue` 及 `BOOK_GENRES` 共享常量的代码变更证据，需补充源码或运行截图以证实「无旧值写入路径」。
2.  **全局零残留声明（中-3）**：因 diff 截断无法审查被移除的执行器及附录 A 源码，需提供完整的 grep 命令输出与 CDP 走查记录。
3.  **嵌套事务回滚的绝对正确性**：静态层面 `d.transaction(() => { d.exec(); m.migrate?.(d); ... })` 逻辑闭环，但 better-sqlite3 嵌套 SAVEPOINT 的边界异常行为需通过运行期注入故障（如模拟 JSON parse 极端错误）来验证回滚一致性。
4.  **重启迁移幂等性**：材料声称「重启迁移幂等（版本 11）」，静态可见 `if (applied.has(m.version)) continue` 守卫，但 JS 数据迁移（retag）若被重复执行是否绝对无害（例如对已映射过的 tags 再次 map），需运行验证。
