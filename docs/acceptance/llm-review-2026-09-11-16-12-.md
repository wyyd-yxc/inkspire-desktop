## 发现的问题

1. **【中等】关键类型契约 `digest.types.ts` 缺失静态证据**
   - **缺陷**：preload 与 `StyleDigestDialog.vue` 均引入了 `DigestPickResult` 和 `DigestResult`，但 diff 在 `services/digestPrompts.ts` 处截断，且全文未包含 `src/shared/digest.types.ts` 的定义。无法静态确认 `DigestPickResult` 是否严格包含 `{fileName, text, totalChars, truncated}`，以及 `DigestResult` 的字段口径是否与 `sanitizeDigest` 一致。
   - **隐患**：若类型定义与实际使用偏差，三重闸门可能因 `any` 或宽泛类型而漏报。
2. **【低】模块封装临时破坏**
   - **缺陷**：`aiWriting.ts` 将原本私有的 `resolveProfile` 直接改为 `export` 供拆书复用，注释自承“M15 将收敛”。这放大了非写作域对核心配置解析的可见性，违背了模块最小暴露原则。
3. **【低】扩展名二次校验冗余**
   - **缺陷**：`digest.ts` 中 dialog 已限定 `extensions: ['txt']`，随后又通过 `path.extname(src).slice(1).toLowerCase() !== 'txt'` 拦截并抛错。正常用户流中此分支不可达，属无效防御。
4. **【低】review 态取消直接销毁全部上下文**
   - **缺陷**：`SyncCandidateDialog` 的 `@close` 直接绑定主弹窗的 `close()`，导致在 review 阶段取消会直接销毁参考文本和解析结果，无法退回 import 态重试。虽符合任务卡隐私口径，但在 AI 解析不稳定时存在体验断层。
