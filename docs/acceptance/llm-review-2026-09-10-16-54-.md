# LLM 审查（glm-5.1）

> 材料来源：material-M13-stats.md

## 结论
**有条件通过**：核心数据层（快照 upsert 语义、删书级联、目标归一化存储）与零 AI 实证充分，但文档对「同日减字 delta 是否转负」存在严重自相矛盾，且前端视图与计算逻辑因 diff 截断完全无法静态核实，需依赖补充材料或运行时验证兜底。

## 逐项核对

1. **保存后快照 upsert**：**可判定部分达成**。代码 `stats.ts` 事务内 SUM + SELECT + INSERT/UPDATE 逻辑正确，`chapters:update` 与 `chapters:delete` 均挂钩 `recordWordSnapshot`，符合首报建基线、同日覆盖末值设计。**疑点**：材料“已知边界”宣称“同日多次减字 delta 缩小不转负”，但代码 `delta = last_total - base_total` 在同日删字时完全允许负数（如 base=1000, 删500字后 last=500, delta=-500），且 r1 附录明确写着“同日删章...转负”。文档与代码逻辑自相矛盾。
2. **统计页 UI**：**无法判定**。diff 截断缺失 `StatsView.vue`，无法静态核实总字数、今日净增、目标进度条及内联编辑清除逻辑。
3. **热力图**：**无法判定**。diff 截断缺失 `statsCalc.ts` 与 `StatsView.vue`，无法核实 347 格周对齐及档位阈值逻辑。
4. **趋势图**：**无法判定**。diff 截断缺失，无法核实 polyline 数据点及 0 基准线。
5. **里程碑**：**无法判定**。diff 截断缺失 `computeMilestones`，无法核实达成日与差距计算。
6. **重启持久**：**可判定达成**。数据均写入 SQLite（`word_count_snapshots` / `books.word_target`），事务提交后即具备标准持久化能力。
7. **删书级联清快照**：**可判定达成**。`database.ts` v14 migration 明确 `REFERENCES books(id) ON DELETE CASCADE`，符合预期。
8. **零 AI/零外部额度/console 零报错**：**可判定零 AI/零外部额度达成**（主进程及 IPC 层无外部网络调用）；**无法判定** console 零报错（属运行时行为，且代码显式 `console.warn` 捕获快照失败，严格意义上非“零报错”）。

## 发现的问题

1. **文档语义自相矛盾（中等）**：验收材料“已知边界”声明“同日多次减字 delta 缩小不转负（负 delta 仅跨日删除场景）”，但代码 `delta = last_total - base_total` 在同日减字时必然产生负数（基线固定，末值下降），且材料附录 A（r1 整改）明确写着“同日删章 last 下降→delta 缩小/转负”。**建议**：修正“已知边界”表述，如实承认同日减字可为负，避免后续维护者误解。
2. **冗余快照写入隐患（低）**：`chapters:update` 仅判断 `input.wordCount !== undefined` 即触发快照。若渲染层更新章节摘要等其他字段时顺带传入未变更的 `wordCount`，将产生无效的 DB 事务写入（仅更新 updated_at）。主进程层无防冗余比对机制，完全依赖渲染层传参控制，有违“数据层防漏报”的严谨性。
3. **`chapters:delete` 快照时序脆弱性（低）**：代码先 `getChapter(id)` 获取 `bookId`，再 `deleteChapter(id)`，最后调 `recordWordSnapshot`。虽然 better-sqlite3 同步调用无并发竞态，但若 `deleteChapter` 内部逻辑变更导致抛异常，`getChapter` 已读取的旧实体与数据库状态将脱节。当前靠 `wrap()` 兜底未产生脏数据，但属于隐性耦合。

## 无法判定项

1. **前端视图与交互**：总字数/净增/目标进度条/热力图/趋势图/里程碑的渲染逻辑及目标编辑保存（含 `saveTarget` 真 bug 的前端 `.trim()` 修复），因 diff 截断缺失 `StatsView.vue` 无法静态审查。
2. **计算纯函数**：`statsCalc.ts` 中的 `buildTrend`/`buildHeatCells`/`computeMilestones` 等核心算法，因 diff 截断缺失无法独立验证其正确性。
3. **侧栏布局溢出修复**：黑盒披露的顶栏 7 pill 单行溢出遮挡修复（改两行布局），因 diff 截断无法确认完整 DOM 结构与样式是否彻底消除遮挡。
4. **运行时行为**：console 零报错、真实键盘防抖时序鉴别、硬刷新后目标进度条 50% 显示，均需运行时环境验证。
