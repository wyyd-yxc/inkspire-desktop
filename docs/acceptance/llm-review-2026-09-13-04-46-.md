## 发现的问题

1. **`AiWritingPanel.vue` 的 `finish()` 缺少 `sealed = true`（中 / 逻辑缺陷）**  
   `append()`、`fail()`、`seal()` 均对密封态做了处理，但 `finish()` 仅调用 `flushBuf()` 而未设置 `sealed = true`。若因网络或异步竞态，在 `finish()` 后仍有延迟 chunk 推入，`append()` 会继续向 `buf` 写入并在 120ms 后上屏，导致“已结束”的面板内容被污染。应与 `fail()` 保持一致，在 `finish()` 中增加 `sealed = true`。

2. **TypeScript 闸门配置存疑（高 / 工程隐患）**  
   自测声明坦承“typecheck 未能捕获未 import 的 watchEffect（运行时 ReferenceError）”。在标准 TypeScript 环境下，未导入的变量必然触发 `TS2304: Cannot find name` 报错。此现象暗示项目存在全局类型污染、`noImplicitAny` 未开启，或 typecheck 脚本存在执行逃逸，需严肃排查类型闸门的有效性。

3. **`ChapterSidebar.vue` 遗留死 Prop `bookId`（低 / 代码规范）**  
   组件重构后，原用于拼接导航路由的 `bookId` 在 `<template>` 与 `<script>` 中已无任何引用，但仍在 `defineProps` 中保留，应随导航职责上移一并清理。

4. **`ChapterSidebar.vue` 全书字数计算在模板内联（低 / 性能与规范）**  
   移除 `totalWords` prop 后，模板中直接使用 `chapters.reduce((s, c) => s + c.wordCount, 0).toLocaleString('zh-CN')`。这在每次组件渲染时均执行 O(N) 遍历计算，违背 Vue 响应式计算属性最佳实践，应提取为 `computed`。
