## 发现的问题

### 🔴 严重

1. **核心修复文件 `aiWriting.ts` 的 diff 缺失**
   验收材料声称"buildSelectionMessages 新签名 (ctx, sel:{text,before,after}, action, customInstruction?)"，但 diff 中**完全没有** `src/renderer/src/services/aiWriting.ts` 的修改。ChapterEditor 调用了 `buildSelectionMessages(writingContext(), selectionTarget ?? {text:'',before:'',after:''}, kind)`——若 aiWriting.ts 实际未改，TS 编译必败。
   - 后果：自测"typecheck 双 0"声明**与代码现状矛盾**，要么 diff 被截断未贴，要么自测结果失真。

2. **PR 范围严重越界（scope creep）**
   本次验收点是"划词上下文衔接修复"，但 diff 新增了完整创世台功能：
   - 新表 `genesis_steps`（含 DB migration v4）
   - 新文件 `src/main/db/genesis.ts`、`src/main/ipc/genesis.ts`
   - preload 新增 `genesis.*` 三方法
   - `BookCard.vue` 新增"创世台"按钮
   - `ChapterSidebar.vue` 新增创世台入口
   - `ChapterEditor.vue` 新增 `bookId` prop、`loadGenesis`/`ensureGenesisLoaded`/`genesisCache`、watch 注入、`runGeneration` 中的 `ensureGenesisLoaded` 调用
   - `isElectron`、`getPresetStyle`、多个 `shared/genesis.types` 符号依赖
   - 注释甚至自承"此前 isElectron 未导入导致 ReferenceError 被静默吞掉"——说明这段代码经历过"修 bug"迭代，应单独评审/验收，却混在划词修复里一并提交。

### 🟡 中等

3. **行内替换的"折叠换行"语义不明**
   `inlineText = text.replace(/\n+/g, '')` 把所有换行压成空串。若 AI 输出形如"井绳冰凉刺骨。\n\n他仰起头…"，采纳后变为"井绳冰凉刺骨。他仰起头…"，**与原段落融合**；但若选区本身跨多行（同一段落内手动换行），输出会丢失作者意图的换行。无文档说明该策略。

4. **`sameParent` 判定可能误判跨段场景**
   `ed.state.doc.resolve(from).sameParent(ed.state.doc.resolve(to))`：在 Tiptap 中，块节点（paragraph）作为父节点，"同一段落内"判定通常成立；但若选区起点在段末、终点在段首（典型"包含段尾 \n"），是否仍 sameParent 取决于 doc 结构。**材料未给边界用例测试**。

5. **`SEL_CTX_WINDOW` 与 aiWriting 中 `SELECTION_CONTEXT_LIMIT` 的同步靠注释而非代码**
   截断窗口 1500 在 ChapterEditor 中以常量 `SEL_CTX_WINDOW` 定义，aiWriting 端另有一个同名常量。注释称"一致"，但**没有共享常量的导入或单元测试**——任一处改 1500→2000 而忘改另一边，AI 收到的窗口就会错位。

6. **`genesisLoadingPromise` 竞态防护不完整**
   `loadGenesis` 用 `genesisLoadSeq` 丢弃过期结果；`ensureGenesisLoaded` 仅 `await genesisLoadingPromise`。若 `bookId` 切换两次：第一次 promiseA pending → 第二次 promiseB pending → 用户立刻点续写，`ensureGenesisLoaded` 等待的是 promiseA 解决后才 resolve 的状态，**可能不包含 B 的结果但却 await 通过**——此时 `genesisCache.value` 是空（B 还没 resolve）。应等当前 seq 的 promise，而非上一个。

7. **DB migration v4 缺前向兼容测试**
   仅 `CREATE TABLE IF NOT EXISTS`，对存量用户的旧 v1/v2/v3 库会一次跑过，OK；但**未在材料中给出"老库升级后创世台表为空且不报错"的回归证据**。

### 🟢 轻微

8. **IPC 通道命名风格不一致**：本仓库其他 IPC 形如 `chapters:list` / `chapters:save`，创世台用了 `genesis:get` / `genesis:save` / `genesis:save-step`，第三方法带连字符，前两者不带，缺统一规范。

9. **preload 类型签名收窄**：`saveStep` 的 `data: unknown` 在 TS 层放弃了类型检查，IPC 边界类型安全退化到运行时（JSON.parse 在 DAO 中兜底为 null）。

10. **BookCard 重复进入路径**：原"封面/标题"区域已可点击进入工作台（`openBook`），现在又加"写作"按钮——视觉/交互冗余，且 `openBook` 既绑在卡片上又绑在按钮上，需 `@click.stop` 拦截，可能误触。
