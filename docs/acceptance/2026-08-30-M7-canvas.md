## 发现的问题

### 问题 1（阻断）：Vue Flow 事件处理器参数签名错误，画布核心交互三项失效

- 位置：`src/renderer/src/views/CanvasView.vue` L139 `onNodeDragStop` / L152 `onNodeClick` / L156 `onNodeDoubleClick`
- 原因：`@vue-flow/core` v1.48 组件事件为**单参数载荷** `{ event, node }`（dragStop 为 `{ event, node, nodes }`），三处处理器却按 `(event, node)` 双参数声明，实际运行时 `node === undefined`：
  - **双击节点** → `Uncaught TypeError: Cannot read properties of undefined (reading 'id')`（实测捕获），编辑面板打不开 → UI 无法编辑场景，也无法删除场景（「删除场景」按钮仅在编辑面板内）；
  - **单击节点** → 同 TypeError，`selectedScene` 永远为 null → 搭桥填缝/改写场景两模式入口被守卫永久拦截（五模式中两模式黑盒不可用）；
  - **拖动节点** → 节点视觉移动，但处理器在 `scenes.value.find((x) => x.id === node.id)` 处抛错（async 函数，拒绝被 dev 模式静默），`scenes.update`/`scenes.reorder` 从未调用 → 位置不落库、不按 x 重排 sort_order（实测 3 次，DB 均无变化）。
- 证据：真实坐标双击后 window.onerror 捕获 4 条同型 TypeError；以真实载荷形态直接调用 `props.onNodeClick({event,node})` 复现同错；拖拽前后 DB 对比 + `window.api.scenes.update/reorder` 打点零调用。
- 影响范围：验收点 1 的编辑/删除 UI、验收点 2 的拖动落库与单击选中、验收点 3 的 bridge/rewrite 两模式、词条挂接的 UI 入口。
- 修复建议：三处统一改为 `function onNodeClick(e: NodeMouseEvent): void { const node = e.node; ... }` 形态；修复后需重验本表 #3/#4/#5/#6/#14 及 bridge/rewrite 两模式。

### 问题 2（轻微）：路由参数变化时画布数据不刷新

- 位置：`CanvasView.vue` L31-32，`bookId/chapterId` 在 setup 一次性取自 `route.params`，无 route watch / `onBeforeRouteUpdate`。
- 现象：`/canvas/ch1` → `/canvas/ch2` 同路由跳转（组件复用）时画布仍显示 ch1 的场景（实测复现：ch2 库中 0 场景、画布显示 2 个旧节点）。
- 缓解：正常 UI 导航（工作台 ↔ 画布）组件重挂载，不受影响；建议对 router-view 加 `:key` 或 watch 路由参数重载。

### 问题 3（轻微）：停止路径与死代码

- `stopEverything()`（L478）仅置 `isBusy=false`，不实际 abort 当前流（依赖 onError('已中止') 驱动，与自测声明一致，但场景生成面板的「■ 停止」按钮无立即中止效果）；`generateOneScene` 中 `session` 变量为死代码（`void session`）。
