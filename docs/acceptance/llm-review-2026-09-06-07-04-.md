## 发现的问题

### 🔴 严重：无新严重问题。沿用二轮 P1，本轮仅做注释登记（详见下方 P1）。

### 🟠 中等

**P1（沿用二轮 P1，本轮仅注释登记，未实际加校验）**
- 现象：`assertWikiRefs` 仅校验 UUID 格式；`plot-edges:create` 完全未校验 `sourceId`/`targetId` 是否属于 `input.bookId`。
- 风险：单用户单机信任边界下虽属低风险（与 M7 同模型），但材料正文未提供「单用户单机」约束条件的合规证据（如威胁模型文档），仅以类比 M7 为由。
- 处置要求：已登记为「后续多档/协同再以 migration + DAO 归属校验补齐」，建议至少在 DAO 层加一道 `book_id` 一致性断言（成本极低、收益明显）。

**P2-新-① `parent_id` 列已建但 M10 全程为 null 的浪费与隐患**
- 现象：migration v10 建 `parent_id TEXT` 列且「故意不加 FK 约束」，M10 全量写 `null`。
- 风险：① 索引未建（`idx_plot_events_book` 只含 `book_id`），未来 M11 加 FK 后子事件查询无索引支撑；② `listPlotEvents(bookId, null)` 走 `parent_id IS NULL` 全扫，无伤但模式已定型。
- 建议：至少建 `CREATE INDEX IF NOT EXISTS idx_plot_events_parent ON plot_events(parent_id)` 备用，或在 M10 阶段直接不建列、待 M11 migration 落地时再加。

**P2-新-② `createPlotEvent` 计数默认值在并发场景下会冲突**
- 现象：`pos_x = (count + 1) * 340`、`title = \`事件 ${count + 1}\``，依赖 `COUNT(*)` 决定默认坐标与默认标题。
- 风险：better-sqlite3 同步调用虽避免同进程内并发，但 IPC handler 层若被并发触发（理论上 Electron 主进程单线程下不会，但 `wrap()` 包裹+Promise 化后跨 await 可能让两次 create 读到同一 count），会生成相同坐标/标题。
- 建议：默认坐标改用 `Math.random()` 或基于 `max(pos_x)+340`；默认标题直接用 `事件 ${shortId}` 或 `新事件`。

### 🟡 低

**P3-① `updatePlotEvent` 未对 `bookId` 做归属校验**
- 现象：`plot:update` 仅 `assertUuid(id)`，未校验该 id 是否属于 `input`（实际上 `UpdatePlotEventInput` 不含 `bookId`），意味着任何持有事件 UUID 的人可越权修改任意书的事件。
- 风险：与 P1 同模型——单机单用户信任边界；但相比 P1 更容易被忽略（事件 id 一旦泄露/在 IPC 日志残留就可被滥用）。
- 建议：`updatePlotEvent` 内部 `getPlotEvent` 后断言 `row.book_id === expectedBookId`（由 IPC handler 传入 bookId，或 DAO 强制要求 input 含 bookId）。

**P3-② `removePlotEvent` / `removePlotEdge` 完全无归属校验**
- 同 P3-①，删除路径同样裸奔。建议至少在 DAO 层做 `book_id` 一致性检查。

**P3-③ `plotStyle.ts` 标签哈希碰撞容忍度过低**
- 现象：`TAG_PALETTE` 仅 8 色，`hash % 8` 极易碰撞（如「伏笔」「悬念」哈希可能撞同一色）。
- 风险：UX 问题，不同语义标签同色会误导作者。
- 建议：扩大色板到 16–24 色，或在哈希中混合 `tag.length` 维度。

**P3-④ `ChapterSidebar.vue` 编辑态 input 的 ref 收集用 `Map<string, HTMLInputElement>`，但未在章节切换/删除时清理**
- 现象：`editInputs` Map 只在 `setEditInputRef` 收到 `null/undefined` 时 `delete`，依赖 `v-for` 销毁时 Vue 会调 ref 回调传 `null`。
- 风险：Vue3 函数 ref 在 `v-for` 中销毁时确实会传 `null`，但若章节 key 复用（极端情况下）可能泄漏。
- 建议：在 `commitRename` 或 `watch(chapters)` 时清理 `editingId` 对应之外的条目。

**P3-⑤ `plotStyle.ts` `reference` 类型文案与 M10 设计是否一致无法核对**
- 现象：材料声明「reference 引用」绿点线，但未提供 M10 设计稿/规范来源。
- 建议：在 `material-M10-plot-canvas.md` 设计章节中追加此约定的出处。
