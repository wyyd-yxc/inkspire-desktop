## 发现的问题

### 中级

**1. v11 题材映射语义可疑——「言情」→「现实主义」**

v11 SQL：
```sql
UPDATE books SET genre = '现实主义' WHERE genre IN ('都市', '言情');
```
「言情」与「现实主义」是正交概念（古代言情、架空言情均非现实主义），此映射会造成数据语义错误且迁移后不可逆（事务成功提交后无法通过回滚纠正）。同理「仙侠」→「奇幻」也有争议但程度较轻。**建议**：提供题材收敛的业务依据，或拆分映射策略。

**2. v11 迁移后 UI 题材选项是否同步更新——无法判定**

v11 仅迁移已有 books.genre 数据。若创建书籍的 UI 选择器仍向用户展示旧选项（玄幻/仙侠/都市/言情/游戏/轻小说），新数据将写入旧值，导致迁移后新旧值共存、数据不一致。diff 截断，未见相关组件变更。**建议**：补充创建书籍表单的题材选项 diff。

**3. diff 仍截断——与一轮高优先级问题同类**

代码变更 diff 末尾标注 `…(diff 已截断)`，`AssistantDock.vue` 的 system prompt 改动仅展示一半，无法审查该文件完整变更，亦无法确认是否还有其他未展示的文件。一轮处置的核心诉求是「补齐截断」，但 diff 本身仍截断，仅靠附录 A 补齐了三个特定文件。

### 低级

**4. SQL 表名拼接——规范违背（无实际注入风险）**

v11 `migrate` 中：
```ts
const rows = db.prepare(`SELECT id, tags FROM ${table}`).all()
const update = db.prepare(`UPDATE ${table} SET tags = ? WHERE id = ?`)
```
`table` 虽来自硬编码（`'plot_events'`/`'scenes'`），无实际注入风险，但直接拼接表名违反参数化查询规范，且 `retag` 作为可复用事务函数接收外部 `table` 参数，未来若调用方传入未预期值将产生风险。**建议**：添加白名单守卫 `if (!['plot_events', 'scenes'].includes(table)) return`。

**5. v11 migrate 标签映射潜在遗漏**

`TAG_MAP` 仅包含 `{ 打斗: '对峙', 感情: '情感' }` 两条。若原有标签体系中还存在其他与严肃化不符的标签值（如「爽点」「金手指」等），v11 不会处理。无法判定是否为有意省略。**建议**：确认标签全集映射覆盖率。
