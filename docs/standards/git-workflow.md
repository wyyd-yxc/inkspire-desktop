# 版本管理规范（Git Workflow）

> 单人 + AI 协作开发，采用最稳妥的「main 单分支 + 约定式提交 + 里程碑标签」模式，不使用复杂分支流。
> 版本：v1.0 · 制定日期：2026-08-22

## 1. 分支模型

- 仅 `main` 一个长期分支，保持随时可运行。
- 大型实验性改动（预计破坏可用性超过一天）可开 `feat/<功能名>` 分支，验收后合回 main 并删除分支。
- **禁止 force push、禁止 rebase 已发布历史。**

## 2. 提交信息规范（约定式提交）

格式：`<类型>: <中文描述>（可附英文关键词）`

| 类型 | 用途 | 示例 |
|---|---|---|
| `feat` | 新功能 | `feat: 书斋支持新建书籍与封面` |
| `fix` | 修 bug | `fix: 修复章节列表排序错乱` |
| `docs` | 仅文档 | `docs: 补充 M1 验收报告` |
| `refactor` | 重构（不改行为） | `refactor: 抽取 IPC 返回类型到 shared` |
| `style` | 界面/样式微调 | `style: 统一卡片圆角与留白` |
| `chore` | 构建/工具/依赖 | `chore: 升级 electron-builder 配置` |
| `test` | 测试相关 | `test: 补充 DAO 单测` |

规则：
- 一次提交只做一件事；提交前 `git status` 确认没有混入无关文件。
- 描述用中文祈使句，结尾不加句号。

## 3. 提交时机

1. **功能提交**：每个可验收功能完成并通过验收后提交。
2. **里程碑标签**：里程碑全部验收通过后打 tag：`v<主>.<次>.<补丁>-<里程碑名>`，如 `v0.1.0-m0-scaffold`、`v0.2.0-m1-bookshelf`。
3. **保险提交**：单次会话工作量较大时，中途做 `chore: WIP <内容>` 保险提交，验收后可 squash 或保留（保留亦可，不追求完美历史，追求不丢工作）。
4. **禁止提交**：`node_modules/`、构建产物、数据库文件、`.env`、任何密钥（.gitignore 已配置，提交前仍需目视检查 `git status`）。

## 4. 恢复纪律（防项目中途出问题）

- 动大手术（跨多文件重构）前：先确认工作区干净或先提交，再动手。
- 删除/重写文件前先 `git log --oneline -- <文件>` 了解历史，必要时先备份分支 `git branch backup/<日期>`。
- 任何「回滚到过去」的操作先在 worklog 登记原因与回滚点。
- tag 是安全锚点：出问题优先 `git diff <上个tag>..HEAD` 定位回归。

## 5. 发布物

- 最终交付：electron-builder 产出的 NSIS 安装包，命名 `InkSpire-Setup-<版本>.exe`，不入库（体积大），只登记校验与路径于 worklog。
